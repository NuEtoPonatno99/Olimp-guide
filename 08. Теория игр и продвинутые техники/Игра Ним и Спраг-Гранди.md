# Игра Ним и Спраг-Гранди

**Теория игр** в олимпиадном смысле — игры **двух игроков** с полной информацией и без случайности, где проигрывает тот, кто **не может сделать ход** (нормальная игра). **Ним** — классическая игра с кучками камней, решаемая **XOR'ом**. **Теорема Спрага–Гранди** обобщает принцип на любые «графовые» игры: каждой позиции ставится число, и проигрыш = ноль.

* **Ним:** ход — убрать **любое** число камней из **одной** кучки. Позиция выигрышная $\iff$ XOR размеров кучек $\neq 0$ (критерий Бутона).
* **Спраг–Гранди:** у каждой позиции есть число Гранди $g(v) = \mathrm{mex}\{g(u)\}$, где $u$ пробегает все позиции, достижимые ходом. Проигрышная позиция $\iff$ $g(v) = 0$.
* **Сумма игр:** если игра распадается на независимые подыгры, общая позиция определяется **XOR'ом** чисел Гранди компонент.
* **$\mathrm{mex}$** — минимальное **неотрицательное** целое, которое не встречается среди чисел детей.

---

## 🛠️ Идея: выигрышные и проигрышные позиции

Раскладываем все позиции на два класса по рекурсивному правилу:

1. **Проигрышная** (P) — нет ни одного хода (конец игры) или **все** ходы ведут к выигрышным.
2. **Выигрышная** (N) — существует хотя бы один ход в проигрышную.

Игрок стремится «отдать» сопернику проигрышную позицию: сделал ход в P — идеальный соперник при любом своём ходе вернёт тебе N, и так до победы.

**Почему в Ниме работает XOR?** Два факта:

* Из позиции с XOR $= 0$ любой ход меняет **одну** кучку, значит итоговый XOR становится $\neq 0$.
* Из позиции с XOR $\neq 0$ берём старший установленный бит $x$, находим кучку, где этот бит есть; уменьшаем её до $p' = p \oplus x$ (старший бит $x$ обнуляется, поэтому $p' < p$) — приходим ровно в нулевой XOR.

Есть ход «в ноль» — позиция выигрышная; нет — проигрышная.

## 💻 Решение Нима и выигрышный ход

```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> piles(n);
    int xr = 0;
    for (int i = 0; i < n; i++) {
        cin >> piles[i];
        xr ^= piles[i];
    }

    if (xr == 0) {
        cout << "Второй игрок выигрывает\n";
    } else {
        // Ищем кучку, которую можно уменьшить до p' = p ^ xr < p
        for (int i = 0; i < n; i++) {
            int target = piles[i] ^ xr;
            if (target < piles[i]) {
                cout << "Ход: кучка " << i + 1 << ": " << piles[i] << " -> " << target << "\n";
                break;
            }
        }
        cout << "Первый игрок выигрывает\n";
    }
    return 0;
}
```

* XOR считается одним проходом: $O(n)$.
* Выигрывающий ход из ненулевого XOR **всегда существует**, и формула $p' = p \oplus x$ находит его без перебора.

## 💻 Числа Гранди и сумма игр

Для произвольной игры строим граф состояний и считаем $\mathrm{mex}$ по всем ходам:

```cpp
#include <vector>
#include <algorithm>

int mex(const vector<int>& vals) {          // минимальное неотрицательное, отсутствующее в vals
    vector<int> v = vals;
    sort(v.begin(), v.end());
    int g = 0;
    for (int x : v) {
        if (x == g) g++;
        else if (x > g) break;
    }
    return g;
}

int grundy(int v, const vector<vector<int>>& next, vector<int>& memo) {
    if (memo[v] != -1) return memo[v];
    vector<int> childG;
    for (int to : next[v]) childG.push_back(grundy(to, next, memo));
    return memo[v] = mex(childG);
}
```

* `memo` — обычная мемоизация из [[Динамическое программирование. Основы]]: каждое состояние считается один раз.
* Лист без ходов даёт `mex({})` $= 0$ — корректная база.
* Несколько независимых подыгр — XOR: `int xr = 0; for (...) xr ^= grundy(...)`.

Пример с периодом. Игра «возьми 1, 2 или 3 камня из кучки»:

```cpp
int g(int n) { return n % 4; }   // периодичность: 0,1,2,3,0,1,2,3,...
```

* Для одной кучки выигрыш при $n \not\equiv 0 \pmod 4$ — тот же принцип, что и «кто досчитает до N».
* Несколько кучек — XOR значений $n \bmod 4$. Интуиция «смотри на остатки по отдельности» тут ломается: работает только XOR.

## 🧮 Где применяется

| Задача                                           | Число Гранди / подход                        |
| :----------------------------------------------- | :------------------------------------------ |
| Ним (кучки камней)                               | XOR размеров: $g(p) = p$                    |
| «Возьми 1..k из кучки» (одна кучка)              | $g(n) = n \bmod (k+1)$                      |
| Игра на графе (фишка ходит по рёбрам)            | $\mathrm{mex}$ по детям из [[Обход BFS и DFS]] |
| Кучка «делится» при ходе (разбиение на две)      | $\mathrm{mex}$ по всем парам-разбиениям     |
| Сумма независимых игр                            | XOR чисел Гранди компонент                  |
| Восстановление выигрышной стратегии              | ход в позицию с XOR / $\mathrm{mex}$ = 0    |

## 🔍 Нюансы

* **Нормальная vs мизерная.** Всё выше — **_нормальная_** игра (проигрывает тот, кто не может ходить). В *мизерной* (проигрывает взявший **последний** камень) критерии меняются, базовая Спраг–Гранди не работает.
* **`mex` — не «порядковый номер».** Это минимальное *отсутствующее* число, а не количество детей: набор `{3, 5}` даёт `0`.
* **Нет хода = проигрышная позиция**, на этом стоит вся рекурсия; «ничейных» состояний в нормальных играх не бывает.
* **Периодичность экономит всё.** Многие игры дают периодическую $g$ — выводите формулу (как $n \bmod (k+1)$) или ищите цикл по предподсчётному массиву.
* **Один XOR на всё.** Компоненты нельзя «усреднять»: каждая вносит в XOR свою $g$, неважно, насколько «большую».
