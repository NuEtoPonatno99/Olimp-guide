# Встреча посередине (Meet-in-the-Middle)

**Meet-in-the-Middle** — приём ускорения перебора: объекты делятся на **две половины**, каждая перебирается отдельно за $2^{n/2}$, и результаты «склеиваются». Итог — $\approx 2^{n/2}$ вместо $2^n$: задачи с $n = 40$ ($2^{20} \approx 10^6$) становятся реальными.

* **Базовая идея:** экспонента $2^n$ заменяется на два перебора по $2^{n/2}$ плюс склейку (сортировка + [[Бинарный поиск]] / [[Два указателя]]).
* **Классика:** subset sum («существует ли подмножество с суммой $S$») при $n \le 40$–$44$.
* **Склейка:** для каждого варианта левой половины ищем «дополнение» в отсортированной правой.
* Смежная техника — [[Рекурсия и перебор]]: её «корневое» ускорение.

---

## 🛠️ Идея: раздели и встреться

Пусть решение — выбор «взять/не взять» для каждого из $n$ элементов. Полный перебор — $2^n$. Делим: левая половина $a[0..m)$, правая $a[m..n)$.

Любое решение = **выбор в левой + выбор в правой**. Переберём:

1. Все суммы левой половины → список `L` размером $2^{n/2}$;
2. Все суммы правой → список `R` размером $2^{n/2}$, **сортируем**;
3. Для каждой суммы из `L` бинарно ищем нужное дополнение в `R`.

Стоимость — $O(2^{n/2} \cdot \log 2^{n/2})$, а не $O(2^n)$. Выигрыш — «корень от экспоненты»: $n = 40$ даёт миллион вариантов, а не триллион.

## 💻 Subset sum: «существует ли сумма S»

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;
using ll = long long;

// Все суммы подмножеств элементов a[l..r)
vector<ll> allSubsetSums(const vector<int>& a, int l, int r) {
    int len = r - l;
    vector<ll> res;
    for (int mask = 0; mask < (1 << len); mask++) {
        ll s = 0;
        for (int i = 0; i < len; i++)
            if (mask & (1 << i)) s += a[l + i];
        res.push_back(s);
    }
    sort(res.begin(), res.end());
    return res;
}

int main() {
    int n;
    ll S;
    cin >> n >> S;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    int mid = n / 2;
    vector<ll> L = allSubsetSums(a, 0, mid);
    vector<ll> R = allSubsetSums(a, mid, n);

    for (ll x : L)
        if (binary_search(R.begin(), R.end(), S - x)) {
            cout << "Да\n";
            return 0;
        }
    cout << "Нет\n";
    return 0;
}
```

* Генерация сумм — цикл по битмаскам: $2^{n/2}$ масок по $n/2$ битов каждая, итого $O(2^{n/2} \cdot n)$.
* `binary_search` на отсортированном `R` — $O(\log 2^{n/2})$, суммарно дёшево.
* Память: два списка по $2^{n/2}$ `long long`; при $n = 40$ это ~2 × 8 МБ — нормально.

## 💻 Склейка без бинарного поиска

Если нужно не «ровно $S$», а «**максимальная** сумма $\le S$», идём двумя указателями — уже $O(2^{n/2})$ после сортировки:

```cpp
ll best = 0;
int j = (int)R.size() - 1;
for (ll x : L) {
    while (j >= 0 && x + R[j] > S) j--;   // правая часть слишком большая
    if (j >= 0) best = max(best, x + R[j]);
}
```

* `L` и `R` отсортированы по возрастанию; `j` отступает, `x` наступает — классика [[Два указателя]].
* Так же считаются: **число пар с суммой $\le S$**, минимум похожих функций, различные «сколько способов».

## 🧮 Где применяется

| Задача                                             | Как делится                                     |
| :------------------------------------------------- | :---------------------------------------------- |
| Subset sum (существует ли сумма $S$)               | половины по $2^{n/2}$, склейка поиском           |
| Максимальная сумма $\le S$ и похожие оптимумы      | половины + [[Два указателя]]                    |
| TSP (коммивояжёр) до $n \approx 40$                | две половины пути, склейка по концам             |
| «Разбей на два множества с условием»               | битовые маски двух половин (см. [[ДП по подмножествам (битмаски)]]) |
| Поиск в большом переборе переменных                | первая половина переменных → вторая              |

## 🔍 Нюансы

* **Память — главное ограничение.** Списки $2^{n/2}$ значений живут целиком в памяти: при $n = 50$ это ~$3{,}4 \cdot 10^7$ `long long` — уже сомнительно. Комфортный потолок $n \le 44$–$46$.
* **Генерация битмасками** проще рекурсивной; если в список заносятся повторяющиеся суммы (дубликаты элементов) — для «есть/нет» не мешает, для подсчёта количества следите за кратностями.
* **Отрицательные числа** не ломают подход: сортировка остаётся сортировкой, поиск дополнения работает при любых знаках.
* **`long long` для сумм:** $n = 40$ и элементы до $10^9$ в `int` не помещаются.
* **Склейка ≠ слияние половин:** идея работает только если ответ — *сумма* независимых выборов; если между половинами есть связи (порядок, пересечения) — это уже другая задача.
