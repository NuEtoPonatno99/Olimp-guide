# Шпаргалка по асимптотикам

**Асимптотика** — порядок роста времени работы при росте входных данных, записываемый через $O(...)$. На олимпиадах главный вопрос — «пройдёт ли решение по времени»: для C++ ориентир — **~$10^8$ простых операций в секунду** (реалистично $2$–$5 \cdot 10^7$ с логарифмами и константами).

* **Порядок важнее константы** при больших $n$, но на $n \le 10^5$ константа может решать исход.
* **TL в 2 секунды** ≈ бюджет $10^7$–$10^8$ базовых операций (асимптотика × константа).
* Практика: **сначала прикинь сложность, потом пиши код**.

---

## 🧮 Какая сложность проходит при каком $n$

| $n$                    | Допустимая сложность              | Типичный алгоритм                             |
| :--------------------- | :-------------------------------- | :--------------------------------------------- |
| $n \le 10$             | $O(n!)$, $O(2^n \cdot n^2)$       | Перебор всех перестановок                      |
| $n \le 20$–$22$        | $O(2^n)$ / $O(2^n \cdot n)$       | [[ДП по подмножествам (битмаски)]]             |
| $n \le 40$–$44$        | $O(2^{n/2})$                      | [[Встреча посередине (Meet-in-the-Middle)]]    |
| $n \le 300$–$500$      | $O(n^3)$                          | Флойд, тройные циклы                           |
| $n \le 2 \cdot 10^4$   | $O(n^2)$                          | Двойной цикл, квадратное ДП                    |
| $n \le 10^5$–$10^6$    | $O(n \log n)$                     | Сортировки, [[Дерево отрезков]], [[Алгоритм Дейкстры]] |
| $n \le 10^7$–$10^8$    | $O(n)$                            | Линейные проходы, [[Префиксные суммы и разности]] |
| $n > 10^8$             | $O(n)$ с малой константой / $O(\log n)$ / формула | только специальные приёмы        |

* «$10^8$» — условность: на одной машине пройдёт $3 \cdot 10^8$, на другой с `long long` и кэш-промахами — в разы меньше.

## 💻 Как посчитать сложность

Смотрим на самую тяжёлую вложенную конструкцию, а не на всё сразу:

```cpp
for (int i = 0; i < n; i++)                    // n итераций
    for (int j = 0; j < n; j++)                // n итераций
        a[(i + j) % n]++;                      // => O(n^2)

for (int i = 0; i < n; i++)                    // ещё n шагов
    b[i] *= 2;                                 // в сумме O(n^2 + n) = O(n^2)

for (int i = 0; i < n; i++) {                  // внутренний цикл сокращает вдвое
    int j = n;
    while (j > 1) j /= 2;                      // => O(n log n)
}
```

* Вложенность **перемножается**, последовательные блоки **складываются**; остаётся доминирующий член.
* Делим на 2 / на $k$ много раз — появляется $\log$: число делений из $n$ до 1 равно $\lceil \log_2 n \rceil$.
* Амортизация: `push_back` в `vector` — $O(1)$ в среднем, [[DSU (СНМ)]] — почти $O(1)$.

## 🧮 Цифры памяти и степени двойки

| Степень  | Значение        | Приблизительно |
| :------- | :-------------- | :------------- |
| $2^{10}$ | $1024$          | ~$10^3$        |
| $2^{20}$ | $1{,}048{,}576$ | ~$10^6$        |
| $2^{30}$ | $1{,}073{,}741{,}824$ | ~$10^9$ |

* `int` — 4 байта, `long long` — 8 байт. Лимит 256 МБ ≈ $6{,}7 \cdot 10^7$ `int` или $3{,}4 \cdot 10^7$ `long long`.
* `vector<int>` из $10^6$ элементов — 4 МБ; `bool[N][N]` при $N = 10^4$ — это 100 МБ, уже на грани.
* Глубина рекурсии > ~$10^5$ — риск переполнения стека (см. [[Рекурсия и перебор]]).

## 🔍 Нюансы

* **Константы решают.** $O(n \log n)$ с плохой константой может проиграть $O(n \sqrt n)$: `unordered_map` против сортировки, рекурсия против итератива, `long double` против `double`.
* **Логарифм растёт медленно:** $\log_2 10^6 \approx 20$, $\log_2 10^9 \approx 30$ — обычно не проблема.
* **Амортизированные $O(1)$** (vector, DSU) честны в среднем; в худшем случае могут быть хуже.
* **Проверяйте на максимальном тесте:** оценка — теория, TL — практика; запас меньше 3–5 раз обычно означает проблему.
* **Ввод — часть бюджета:** `cin` без `ios::sync_with_stdio(false)` может съесть весь TL ([[Быстрый ввод-вывод]]).
