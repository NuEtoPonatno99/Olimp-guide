# Китайская теорема об остатках

**Китайская теорема об остатках (CRT)** решает системы сравнений:

$$x \equiv a_1 \pmod{m_1}, \quad x \equiv a_2 \pmod{m_2}, \quad \dots, \quad x \equiv a_k \pmod{m_k}$$

Если модули **попарно взаимно просты**, решение существует и единственно по модулю $M = m_1 \cdot m_2 \cdots m_k$.

* **Сложность:** $O(k \log M)$ — на каждый модуль нужен один [[Расширенный алгоритм Евклида|расширенный Евклид]].
* **Условие применимости классической формулы:** $\gcd(m_i, m_j) = 1$ для всех $i \ne j$.
* **Общий случай:** модули не взаимно просты — есть либо бесконечно много, либо ноль решений; проверяется и решается слиянием пар сравнений.
* **Типичные применения:** восстановление большого числа по остаткам, хэширование по нескольким модулям, восстановление результата подстановкой.

---

## 🛠️ Идея и формула

Ищем $x$ в виде суммы частей, каждая из которых «работает» по своему модулю. Пусть $M_i = M / m_i$ — произведение всех модулей, кроме $i$-го, и $t_i$ — обратный к $M_i$ по модулю $m_i$ (он существует, так как $\gcd(M_i, m_i) = 1$). Тогда:

$$x \equiv \sum_{i=1}^{k} a_i \cdot M_i \cdot t_i \pmod M$$

Почему работает: член $a_i M_i t_i$ по модулю $m_i$ равен $a_i$ (так как $M_i t_i \equiv 1$), а по всем остальным модулям $m_j$ делится на $m_j$ нацело (в $M_i$ заделан $m_j$), то есть равен $0$.

```cpp
#include <iostream>
#include <vector>

using namespace std;

using ll = long long;

ll egcd(ll a, ll b, ll& x, ll& y) {
    if (b == 0) { x = 1; y = 0; return a; }
    ll x1, y1, g = egcd(b, a % b, x1, y1);
    x = y1;
    y = x1 - (a / b) * y1;
    return g;
}

// Обратный к a по модулю m (gcd(a,m) == 1)
ll modInverse(ll a, ll m) {
    ll x, y;
    egcd(a, m, x, y);
    return (x % m + m) % m;
}

// CRT для попарно взаимно простых модулей, a[i] < m[i]
ll crt(const vector<ll>& a, const vector<ll>& m) {
    ll M = 1;
    for (ll mi : m) M *= mi;

    ll x = 0;
    for (int i = 0; i < (int)a.size(); i++) {
        ll Mi = M / m[i];
        ll ti = modInverse(Mi % m[i], m[i]); // Mi % m[i]: не тащить огромное Mi в Евклид
        x = (x + a[i] * (Mi % M) * ti) % M;
    }
    return x;
}

int main() {
    vector<ll> a = {2, 3, 2};   // x ≡ 2 (mod 3)
    vector<ll> m = {3, 5, 7};   //     ≡ 3 (mod 5)
    cout << crt(a, m) << endl;  //     ≡ 2 (mod 7)  →  x = 23
    return 0;
}
```

> [!⚠️] Переполнение в $M$ и промежуточных произведениях
> $M$ и $M_i$ растут как произведение модулей — это естественный предел CRT. Считайте в `long long` и приводите к модулю по шагам (`Mi % m[i]`, `Mi % M`). Если модулей много — нужен `__int128` или CRT поверх другого CRT.

## 💻 Непопарно взаимно простые модули

Если $\gcd(m_i, m_j) > 1$, классическая формула не работает. Тогда сливаем сравнения попарно: пусть есть $x \equiv a_1 \pmod{m_1}$ и $x \equiv a_2 \pmod{m_2}$. Подставляем $x = a_1 + k m_1$ во второе:

$$a_1 + k m_1 \equiv a_2 \pmod{m_2} \iff m_1 k \equiv a_2 - a_1 \pmod{m_2}$$

Решаем это линейное сравнение через [[Расширенный алгоритм Евклида]] и получаем новое сравнение с модулем $\text{НОК}(m_1, m_2)$.

```cpp
ll solveLinear(ll a, ll b, ll mod) { // a*x ≡ b (mod), возвращает x в [0, mod) или -1
    ll x, y, g = egcd(a, mod, x, y);
    if (b % g != 0) return -1;       // решений нет
    ll step = mod / g;
    x = x * (b / g) % step;
    return (x % step + step) % step;
}

// Слияние двух сравнений в одно: "как решить CRT в общем виде"
bool mergeCrt(ll a1, ll m1, ll a2, ll m2, ll& resA, ll& resM) {
    ll x, y, g = egcd(m1, m2, x, y);
    if ((a2 - a1) % g != 0) return false;        // системы несовместны

    ll lcm = m1 / g * m2;                        // новый модуль
    ll k = (a2 - a1) / g * x;                    // k из уравнения m1*k ≡ a2-a1 (mod m2)
    k = (k % (m2 / g) + (m2 / g)) % (m2 / g);    // нормализация

    resM = lcm;
    resA = (a1 + m1 * k) % lcm;
    return true;
}
```

Несовместность — реальное явление: например, $x \equiv 1 \pmod 2$ и $x \equiv 0 \pmod 4$ решений не имеют (чётное число не бывает одновременно и нечётным остатком 1, и остатком 0).

## 🔍 Где применяется

| Задача                                        | Решение через                                              |
| :-------------------------------------------- | :--------------------------------------------------------- |
| Восстановление числа по остаткам от деления   | Классический CRT                                           |
| Хэш от большого числа без BigInt              | Хранить остатки по 2–3 простым модулям, восстанавливать CRT'ом |
| Ответ по «умеренному» модулю через готовые модули операций | CRT по нескольким простым модулям                  |
| Системы, где модули не взаимно просты         | Слияние сравнений по парам                                 |
| Генерация псевдослучайных чисел (линейные конгруэнции) | CRT по составному модулю из простых множителей |

## 🔍 Нюансы

* **Обратный в формуле** надо брать к $M_i \bmod m_i$, а не к огромному $M_i$: результат тот же, а [[Расширенный алгоритм Евклида|Евклиду]] меньше работы и нет переполнения.
* **Единственность решения — по модулю $M$:** все решения отличаются на $k M$, так что вывод `x % M` в диапазон $[0, M)$ обязателен.
* **«Огромный $M$» — граница применимости:** если произведение модулей не влезает ни в какой тип — используйте **Garner** (пошаговое восстановление, аккуратно с остатками) или BigInt.
* **CRT и [[Комбинаторика]]:** восстановление результата по остаткам от составного считающего модуля — стандартный приём, чтобы посчитать сочетания с большим $n$ у Лукаса по нескольким простым.
