# Оптимизации ДП

**Оптимизации ДП** — приёмы, ускоряющие пересчёт переходов, когда «наивное» ДП правильное, но медленное. Обзорно: три главных техники и их асимптотики.

* Общая идея — не перебирать все переходы, а вычислять минимум/максимум окна или семейства функций умнее.
* Каждая техника работает **только для своего вида рекурренты** — сначала приведите задачу к виду, потом применяйте.
* Наивная таблица и восстановление — из [[Динамическое программирование. Основы]].

## 🧮 Монотонная очередь (Monotonic Queue / sliding window)

Рекуррента, где переход берёт минимум/максимум по **скользящему окну** последних состояний:

$$dp[i] = \min_{j \in [i-L, i-1]} dp[j] + cost(i)$$

Наивно — $O(n \cdot L)$. Держим deque из пар `(значение, индекс)`, где значения расположены по возрастанию: тогда минимум всегда в голове, а выпавшие из окна индексы удаляются с головы.

Классика: кузнечик, прыгающий на расстояние от 1 до $L$, плата за клетку — минимизировать стоимость пути.

```cpp
// Минимальная стоимость добраться до n-й клетки, прыжки 1..L, плата a[i] за клетку i
#include <iostream>
#include <deque>
#include <vector>

using namespace std;

int main() {
    int n, L;
    cin >> n >> L;
    vector<long long> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    deque<pair<long long, int>> dq; // (dp[i], i); значения монотонно растут
    vector<long long> dp(n, 0);
    dq.push_back({0, -1}); // «виртуальная» стартовая клетка -1 со стоимостью 0

    for (int i = 0; i < n; i++) {
        // удаляем те, что выпали из окна [i-L, i-1]
        while (!dq.empty() && dq.front().second < i - L) dq.pop_front();

        dp[i] = dq.front().first + a[i];          // минимум по окну

        while (!dq.empty() && dq.back().first >= dp[i]) dq.pop_back(); // держим возрастание
        dq.push_back({dp[i], i});
    }

    cout << dp[n - 1] << endl;
    return 0;
}
```

* Каждая позиция входит в deque и выходит из него ровно один раз → всего $O(n)$ вместо $O(n \cdot L)$.
* Это «скользящее окно»; по духу близко к [[Два указателя]], но окно движется только вперёд и не сворачивается.

## 📈 Convex Hull Trick (CHT)

Рекуррента, где переход — минимум **семейства прямых** в точке:

$$dp[i] = \min_j (m_j \cdot x_i + b_j)$$

Прямая $y = m_j x + b_j$ соответствует «входу из состояния $j$», а $x_i$ — параметр состояния $i$. Нужно быстро находить нижнюю огибающую прямых в точке $x_i$.

Типичный пример: `dp[i] = min_j (dp[j] + (a_i - a_j)^2)` раскрывается в $dp[j] + a_j^2 - 2 a_j \cdot a_i + a_i^2$, то есть прямые $m_j = -2 a_j$, $b_j = dp[j] + a_j^2$, запросы $x_i = a_i$.

* **Наклоны добавляются по возрастанию и запросы $x_i$ монотонны** → очередь (deque) с удалением «бесполезных» прямых: амортизированный $O(1)$ на переход, итого $O(n)$.
* **Общий случай** (наклоны/запросы какие угодно) → **дерево Ли-Чао** (Li Chao tree): $O(\log C)$ на добавление и запрос, итого $O(n \log C)$, где $C$ — диапазон значений $x$.

## 🍂 Divide & Conquer DP (D&C DP)

Рекуррента «разбить первые $i$ элементов на $k$ групп»:

$$dp[k][i] = \min_{j < i} \big(dp[k-1][j] + cost(j+1, i)\big)$$

Наивно — $O(k \cdot n^2)$. Но если **точка перегиба монотонна** ($opt[k][i] \le opt[k][i+1]$, где $opt$ — индекс $j$, дающий минимум), строку $k$ можно считать рекурсивно: делим диапазон `i` пополам, а допустимый диапазон для $opt$ сужаем монотонными границами.

```cpp
// Слой k: вычисляем dp[k][l..r]; оптимум ищем только в [optL, optR]
long long cost(int l, int r); // быстро (часто O(1) через префиксные суммы)

void dc(int k, int l, int r, int optL, int optR) {
    if (l > r) return;
    int m = (l + r) / 2, bestOpt = optL;
    for (int j = optL; j < m && j <= optR; j++) { // перебор оптимума — только нужная часть
        long long v = dp[k - 1][j] + cost(j + 1, m);
        if (v < dp[k][m]) { dp[k][m] = v; bestOpt = j; }
    }
    dc(k, l, m - 1, optL, bestOpt);      // левая половина: оптимум не левее
    dc(k, m + 1, r, bestOpt, optR);      // правая половина: оптимум не правее
}
```

Суммарно каждый слой обрабатывает $O(n \log n)$ позиций → $O(k \cdot n \log n)$ вместо $O(k \cdot n^2)$.

| Оптимизация            | Вид рекурренты                                               | Было              | Стало                     |
| :--------------------- | :----------------------------------------------------------- | :---------------- | :------------------------ |
| **Монотонная очередь** | $dp[i]=\min\limits_{j \in [i-L,i-1]} dp[j]+cost(i)$          | $O(n \cdot L)$    | $O(n)$                    |

## 🔍 Нюансы

* **Строгий вид рекурренты обязателен:** каждая техника заточена под свою формулу. Не форсируйте — иногда проще ускорить проверками (отсечениями) или аналитической формулой.
* **`cost(j+1, i)` в D&C DP** должна считаться за $O(1)$ или $O(\log n)$ — часто через [[Префиксные суммы и разности]]. Правильная оценка стоимости — половина успеха.
* **Монотонная очередь против всех:** единственная из трёх, у которой нет условий на вид функции, кроме «минимум/максимум по окну» — поэтому встречается чаще всего.
* **Проверка монотонности $opt$:** для CHT и D&C DP главный критерий применимости — монотонность наклонов/запросов или точек перегиба. Её проверяют на тестах или доказывают перестановочным неравенством (алгеброически).
* **Связь с базой:** это всё ещё ДП из [[Динамическое программирование. Основы]] — только переход считается быстрее.
