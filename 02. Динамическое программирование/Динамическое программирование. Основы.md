# Динамическое программирование. Основы

**Динамическое программирование (ДП)** — метод решения задач, в котором задача разбивается на **перекрывающиеся подзадачи**: каждая подзадача решается ровно один раз, а готовый ответ сохраняется в таблице и переиспользуется.

* **Главная конструкция — рекуррента:** `dp[i] = f(dp[меньших состояний])`. Таблица и циклы — лишь техника её исполнения.
* **Сложность по времени:** $O(\text{число состояний} \times \text{число переходов из одного состояния})$.
* **Две формы записи:** рекурсия с мемоизацией и итеративная таблица (bottom-up). Результат одинаковый.
* **Восстановление ответа:** параллельный массив `from` / `prev` хранит «откуда пришли» — тогда можно вытащить не только значение, но и само решение.

---

## 🛠️ Идея: почему таблица быстрее рекурсии

Возьмём числа Фибоначчи. Наивная рекурсия `fib(n) = fib(n - 1) + fib(n - 2)` пересчитывает **одни и те же** подзадачи по многу раз — дерево вызовов разрастается до $O(2^n)$ и `fib(50)` уже «висит» вечно.

* **Мемоизация:** запомнили результат в массиве → каждое состояние считается один раз → $O(n)$.
* **Таблица (итеративно):** заполняем массив от меньших индексов к большим, снизу вверх. То же самое, но без рекурсии и стека.

Дальше три кита, на которых стоит любая задача ДП:

1. **Рекуррента** — как выразить `dp[...]` через меньшие состояния.
2. **Таблица** — где храним и в каком порядке заполняем.
3. **Восстановление ответа** — массив «откуда пришли», если нужен сам маршрут/набор, а не только значение.

## 💻 Пример 1: кузнечик (рекуррента + таблица)

Классика. Кузнечик стоит на клетке `0` и прыгает на `1` или `2` клетки вперёд. Сколько способов добраться до клетки `n`?

Рекуррента: добраться до `i` можно либо прыжком на 1 из `i-1`, либо прыжком на 2 из `i-2`:

$$dp[i] = dp[i - 1] + dp[i - 2], \qquad dp[0] = 1$$

```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    int n;
    cin >> n;

    vector<long long> dp(n + 1, 0);
    dp[0] = 1; // база: до клетки 0 — ровно один способ (стоять на месте)

    for (int i = 1; i <= n; i++) {
        if (i - 1 >= 0) dp[i] += dp[i - 1]; // пришли прыжком на 1
        if (i - 2 >= 0) dp[i] += dp[i - 2]; // пришли прыжком на 2
    }

    cout << dp[n] << endl;
    return 0;
}
```

* Таблица заполняется строго от меньших индексов к большим — рекуррента ссылается только на уже посчитанные клетки.
* `long long`: количество способов растёт быстрее, чем кажется ($dp[90]$ уже не влезает в `int`).

## 💻 Пример 2: размен монет (восстановление ответа)

Задача: разменять сумму $S$ монетами из набора `coins`, использовав **минимум** монет. Нужно вывести не только количество, но и сами монеты.

Рекуррента:

$$dp[s] = \min_{c \le s} dp[s - c] + 1, \qquad dp[0] = 0$$

Массив `from[s]` запоминает, **какой монетой** добирали сумму $s$. В конце идём от $S$ назад по `from` — это и есть восстановление ответа.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

int main() {
    int S, k;
    cin >> S >> k;
    vector<int> coins(k);
    for (int i = 0; i < k; i++) cin >> coins[i];

    const int INF = 1e9;
    vector<int> dp(S + 1, INF);
    vector<int> from(S + 1, -1); // «откуда пришли» — какая монета добавилась
    dp[0] = 0;                   // сумму 0 размениваем нулём монет

    for (int s = 1; s <= S; s++) {
        for (int c : coins) {
            if (c <= s && dp[s - c] + 1 < dp[s]) {
                dp[s] = dp[s - c] + 1;
                from[s] = c; // запомнили выбор
            }
        }
    }

    if (dp[S] == INF) {
        cout << "Разменять невозможно" << endl;
        return 0;
    }
    cout << "Минимум монет: " << dp[S] << endl;

    cout << "Монеты:";
    for (int s = S; s > 0; s -= from[s]) { // идём НАЗАД по from
        cout << " " << from[s];
    }
    cout << endl;
    return 0;
}
```

> [!⚠️] Восстановление — обратный проход
> Само значение вы получаете после единственного прохода таблицы. Чтобы получить **набор** (монеты, предметы, путь), нужно пройти по массиву `from` от конца к началу. Поэтому `from` и называется «откуда пришли».

## 💻 Альтернативная форма: рекурсия с мемоизацией

Иногда рекурсивно писать естественнее (переходы неочевидны, порядок обхода сложный). Та же таблица, но заполняется «по требованию»:

```cpp
#include <iostream>
#include <vector>

using namespace std;

vector<long long> memo;

long long fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];        // уже считали — берём готовый ответ
    return memo[n] = fib(n - 1) + fib(n - 2); // считаем ровно один раз
}

int main() {
    int n;
    cin >> n;
    memo.assign(n + 1, -1);
    cout << fib(n) << endl;
    return 0;
}
```

Разница между формами сводится к вкусу и глубине рекурсии:

|                     | Наивная рекурсия                    | Рекурсия + мемоизация        | Итеративная таблица          |
| :------------------ | :---------------------------------- | :--------------------------- | :--------------------------- |
| **Число подзадач**  | пересчитывает одно и то же          | каждая один раз              | каждая один раз             |
| **Доп. память**     | стек $O(n)$                         | таблица $O(n)$ + стек        | таблица $O(n)$              |
| **Скорость**        | $O(2^n)$                            | $O(\text{число состояний})$  | $O(\text{число состояний})$ |
| **Переполнение стека** | риск                             | риск на глубокой рекурсии    | нет                          |

## 🧮 Рецепт: как «придумать ДП»

1. **Состояние** — что означают индексы таблицы (что уже решено: клетка, сумма, количество предметов).
2. **Рекуррента** — как `dp[...]` выражается через меньшие состояния. Проверьте её на паре маленьких примеров вручную.
3. **База** — значения, которые рекуррентой не выражаются (`dp[0]`, пустое состояние).
4. **Порядок обхода** — заполняем от самых простых подзадач к сложным так, чтобы все нужные для перехода значения уже стояли в таблице.
5. **Восстановление** — если нужен сам ответ (набор, путь), заводите `from` и запоминайте выбор.

Классическая оценка: **сложность = число состояний × число переходов**. Во всех примерах этапа: `[[Рюкзак]]`, `[[ДП по подмножествам (битмаски)]]`, `[[Цифровая динамика]]`, `[[ДП на деревьях]]`.

## 🔍 Нюансы

* **Переполнение:** суммы и особенно *количества способов* растут быстро — `long long`, а при необходимости и модуль.
* **ДП ≠ перебор:** в [[Рекурсия и перебор]] каждая ветка перебирается отдельно и общие подзадачи пересчитываются. ДП запоминает каждую подзадачу один раз — разница видна на Фибоначчи ($2^n$ против $O(n)$).
* **Итеративность:** [[Алгоритм Флойда-Уоршелла]] — классический пример ДП: рекуррента «путей через промежуточную вершину $k$» и тройной цикл по таблице `distanceMatrix`.
* **Очередность циклов** иногда неочевидна (например, у кузнечика — строго по возрастанию `i`). Если рекуррента ссылается на состояния «вбок» — продумайте порядок отдельно.
* **Оптимизации:** если наивная таблица медленная, смотрите [[Оптимизации ДП]] — монотонная очередь, Convex Hull Trick, divide & conquer DP.
