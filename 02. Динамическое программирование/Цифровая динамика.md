# Цифровая динамика

**Цифровая динамика** — ДП «по разрядам числа». Позволяет отвечать на вопросы вида «сколько чисел от $L$ до $R$ обладают свойством $P$» за $O(\text{число разрядов} \times \text{количество состояний})$, даже если $R \sim 10^{18}$.

* **Главный трюк:** `answer(L, R) = count(R) - count(L - 1)`.
* **Ключевое состояние — `tight`** («прижатость к границе»): пока префикс числа совпадает с префиксом верхнего предела, дальше нельзя поставить цифру, большую его цифры. Это и есть *too-close-to-bound* техника.
* **Условие задачи** добавляется дополнительными состояниями (сумма цифр, счётчик цифр и т.д.).

---

## 🛠️ Идея: строим число по разрядам

Число собираем слева направо, разряд за разрядом. Состояние рекурсии:

* `pos` — сколько разрядов уже выбрано;
* `tight` — флаг «мы пока идём ровно по цифрам предела $N$».

Если `tight = 1`, на текущую позицию можно ставить только цифры $d \le N[pos]$; как только поставили цифру **меньше** — `tight` сбрасывается и дальше можно ставить что угодно ($0..9$). Вот и вся магия: после разрыва с границей свобода полная.

Рекуррента на примере «числа от 0 до $N$ без запрещённой цифры»:

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <functional>

using namespace std;
using int64 = long long;

// Сколько чисел от 0 до s, в записи которых нет цифры dBad.
int64 solve(const string& s, int dBad) {
    int n = (int)s.size();
    // memo[pos][tight] — одни и те же (pos, tight) встречаются много раз → мемоизация
    vector<vector<int64>> memo(n, vector<int64>(2, -1));

    function<int64(int, bool)> dfs = [&](int pos, bool tight) {
        if (pos == n) return (int64)1;          // число построено целиком
        if (memo[pos][tight] != -1) return memo[pos][tight];

        int64 res = 0;
        int limit = tight ? s[pos] - '0' : 9;   // граница для текущего разряда
        for (int d = 0; d <= limit; d++) {
            if (d == dBad) continue;            // цифра под запретом
            res += dfs(pos + 1, tight && (d == limit));
        }
        return memo[pos][tight] = res;
    };
    return dfs(0, true);
}

int main() {
    long long L, R;
    cin >> L >> R;

    // Числа без цифры 4 на отрезке [L, R]:
    int64 r = solve(to_string(R), 4);
    int64 l = (L == 0) ? 0 : solve(to_string(L - 1), 4);
    cout << r - l << endl;

    return 0;
}
```

* `limit = tight ? s[pos] - '0' : 9` — единственное место, где `tight` влияет на перебор.
* `tight && (d == limit)` — флаг остаётся включённым только если цифра ровно попала в границу.
* `solve` считает от **0** включительно: на интервале `[L, R]` единица от нуля сокращается, а при `L = 0` ответ и есть `solve(R)` (если сам `0` не должен считаться — вычтите лишнюю единицу).

## 🧮 Дополнительные состояния: как описать «свойство P»

Ровно та же схема, но к `(pos, tight)` добавляется ещё одно измерение под условие задачи:

| Свойство                                          | Дополнительное состояние        |
| :------------------------------------------------ | :------------------------------ |
| Сумма цифр делится на $k$                         | `s % k`                         |
| Содержит ровно $t$ цифр «4»                       | счётчик `cnt`                   |
| Нет двух подряд идущих одинаковых цифр            | предыдущая цифра `last`         |
| Число кратно $m$                                  | `val % m` (остаток от деления)  |

Каждое такое состояние — ещё одна размерность массива `memo`. Рекуррента остаётся той же: на `dfs` просто передаются ещё пара-тройка параметров (например, `dfs(pos, tight, sum, cnt)`).

Частные случаи «свойства» превращаются в базу: на `pos == n` проверяем итог по накопленным состояниям (делится сумма цифр? ровно ли $t$ четвёрок?) вместо безусловной единицы.

## 💻 Пример с состоянием: сколько чисел ≤ N без пары подряд идущих «1»

Тот же каркас, но с памятью о предыдущей цифре. Заодно видно, почему **ведущие нули** тут требуют аккуратности:

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <functional>

using namespace std;
using int64 = long long;

// Числа от 0 до s; запрещена пара подряд идущих цифр 1 (цифра dPrev была раньше слева)
int64 solve(const string& s) {
    int n = (int)s.size();
    // memo[pos][tight][last]: last = 0..9 предыдущая цифра, 10 = «число ещё не началось»
    vector<vector<vector<int64>>> memo(n,
        vector<vector<int64>>(2, vector<int64>(11, -1)));

    function<int64(int, bool, int)> dfs = [&](int pos, bool tight, int last) {
        if (pos == n) return (int64)1;
        if (memo[pos][tight][last] != -1) return memo[pos][tight][last];

        int64 res = 0;
        int limit = tight ? s[pos] - '0' : 9;
        for (int d = 0; d <= limit; d++) {
            if (d == 1 && last == 1) continue; // сейчас 1 сразу после 1 — запрет
            res += dfs(pos + 1, tight && (d == limit), d);
        }
        return memo[pos][tight][last] = res;
    };
    return dfs(0, true, 10); // 10 — «цифр ещё не было», так что первая 1 разрешена
}
```

Пара «1,1» от ведущих нулей, к счастью, не возникает: дописываются только нули. А вот у свойств вида «нет двух **подряд одинаковых** цифр» ведущие нули становятся настоящими цифрами и ломают подсчёт чисел с меньшим числом разрядов — для числа «5» маска «005» порядок `0, 0, 5` даёт пару одинаковых соседей, которой в исходном числе нет. Тогда нужен флаг `started` («запись числа уже началась»), который первые нули не считает цифрами.

> [!⚠️] Ведущие нули vs сами цифры
> Для свойства «нет цифры 4» ведущие нули безобидны (нуль не запрещён) — как в первом примере. Для свойств про *соседство* или *значение цифр* — обязательно вводите флаг `started`.

## 🔍 Нюансы

* **Отрезок через разность:** `count(R) - count(L - 1)` — стандартная обвязка для всех задач «от $L$ до $R$».
* **Число или строка:** при $N \le 10^{18}$ удобно держать `s = to_string(N)` — разряды как символы, никакой арифметики.
* **Типы:** количество чисел до $10^{18}$ влезает только в `long long` (и доходит почти до $10^{18}$ — предел значения).
* **Мемоизация:** она корректна только по тем параметрам, от которых *будущие* переходы действительно зависят: `tight` влияет, прошлые конкретные цифры — обычно нет (кроме добавленных состояний как `last`).
* **Связь:** каркас рекурсии с мемоизацией — из [[Динамическое программирование. Основы]]; «поиск границы» часто комбинируется с бинарным поиском из [[Бинарный поиск]] (наименьший $N$, где свойство выполняется).
