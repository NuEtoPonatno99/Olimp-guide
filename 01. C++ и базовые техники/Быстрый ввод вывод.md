# Быстрый ввод-вывод

**Быстрый ввод-вывод** — набор приёмов, которые ускоряют чтение и запись данных. На олимпиадах время решает всё: вход из $10^6$ чисел через медленный `cin` может занять больше времени, чем сам алгоритм.

* **Проблема:** стандартные `cin`/`cout` на больших объёмах данных работают в 10–50 раз медленнее, чем требуется.
* **Когда критично:** вход из $\ge 10^5$ чисел, много строк, задачи с TL (time limit) в 1–2 секунды.
* **Сложность по времени:** $O(n)$ на ввод/вывод, но с правильной настройкой константа в $10^+$ раз меньше.

---

## 🛠️ Почему стандартный ввод такой медленный

1. **Синхронизация с C:** Потоки C++ по умолчанию синхронизированы с потоками C (`scanf`/`printf`), чтобы можно было их смешивать. Поддержка этой синхронизации стоит дорого.
2. **Буферизация:** `cin` при каждом чтении может обращаться к медленному системному вызову вместо чтения большого куска в буфер.
3. **`endl`:** Сброс буфера (`flush`) — очень дорогая операция. В цикле из $10^5$ выводов `endl` убивает скорость.

## 💻 Минимальный набор оптимизаций

Двух строк в начале `main()` достаточно в 90% задач:

```cpp
#include <iostream>

using namespace std;

int main() {
    // Отключить синхронизацию C++-потоков с C-потоками
    ios::sync_with_stdio(false);
    // Развязать cin и cout: не сбрасывать cout перед каждым чтением
    cin.tie(nullptr);
    // ОБЯЗАТЕЛЬНО, если хотите, чтобы cout работал быстро
    cout.tie(nullptr);

    int n;
    cin >> n; // Теперь это быстро

    // Никогда не используйте endl в циклах!
    // cout << x << '\n';  — правильно
    // cout << x << endl;  — долго (лишний flush на каждой итерации)

    return 0;
}
```

> [!⚠️] `#include <bits/stdc++.h>`
> На Codeforces и многих региональных олимпиадах разрешён `#include <bits/stdc++.h>` — он подтягивает весь STL одной строкой. Но на некоторых площадках его нет, поэтому в этой базе всегда пишутся конкретные заголовки.

## 🚀 Кастомный быстрый сканер (когда даже `cin` не спасает)

Если ввод огромный (мегабайты, десятые доли секунды) — читаем всё блоками через `fread`. Пример полностью компилируемой программы, суммирующей $N$ чисел:

```cpp
#include <cstdio>

using namespace std;

const int BUFSIZE = 1 << 20; // Буфер 1 МБ
char buf[BUFSIZE];
int pos = 0, len = 0;

// Читаем следующий символ; 0 означает конец файла (EOF)
inline char getChar() {
    if (pos == len) {                 // Буфер кончился — читаем следующий кусок
        len = fread(buf, 1, BUFSIZE, stdin);
        pos = 0;
        if (len == 0) return 0;       // EOF
    }
    return buf[pos++];
}

// Читаем целое число (поддерживает отрицательные)
inline int readInt() {
    int x = 0, sign = 1;
    char c = getChar();
    while (c <= ' ' && c != 0) c = getChar(); // Пропускаем пробелы/переводы строк
    if (c == '-') { sign = -1; c = getChar(); }
    while (c > ' ') {                          // Пока цифра (код > 32)
        x = x * 10 + (c - '0');
        c = getChar();
    }
    return x * sign;
}

int main() {
    int n = readInt();
    long long sum = 0; // Сумма может не влезть в int!
    for (int i = 0; i < n; i++) {
        sum += readInt();
    }
    printf("%lld\n", sum);
    return 0;
}
```

## 📊 Сравнение способов ввода

| Способ                          | Скорость    | Когда выбирать                                        |
| :------------------------------ | :---------- | :---------------------------------------------------- |
| `cin` без настроек              | 🐢 медленно | Только отладочные программы                           |
| `cin` + `ios::sync_with_stdio`  | 🚀 быстро   | **Стандарт для олимпиад** — почти все задачи           |
| `scanf`/`printf`                | 🚀 быстро   | Если привычнее C-стиль, тоже отлично                   |
| Буфер через `fread`             | ⚡ максимально быстрая | Гигантский ввод, жёсткий лимит времени        |
| `getchar_unlocked()`            | ⚡ быстрая  | Linux-компиляторы (на Windows нет)                    |

## 🔍 Нюансы и подводные камни

* **Не смешивайте** `cin` и `scanf` после отключения синхронизации — данные начнут читаться мимо буфера и сломаются.
* **Типы данных:** всегда думайте об переполнении. Сумма/произведение из $10^5$ чисел легко бьют через `int` — используйте `long long`.
* **Чтение до конца файла:** обрабатываем вход без знания $N$ через `while (cin >> x) { ... }`.
* **Вывод построчно:** всегда `'\n'`, не `endl`.
* **Рекурсия:** при глубокой рекурсии (> $10^5$ вызовов) стек может переполниться. Либо переписывайте итеративно, либо (на Linux) увеличьте стек через `ulimit`/`setrlimit`.
* **`INF`:** константа «бесконечность» для кратчайших путей обычно `1e9` для `int` (`int` максимум $\approx 2.1 \times 10^9$). Для `long long` — `1e18`.

> [!💡] Правило размера
> Если в задаче решение за $O(n)$ — асимптотика норм, но с $10^7$ операций в C++ начнутся проблемы с TL. Оптимизации ввода решают до ~$10^6$–$10^7$ чисел за секунду.
