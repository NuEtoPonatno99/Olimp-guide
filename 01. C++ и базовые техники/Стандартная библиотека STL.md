# Стандартная библиотека STL

**STL (Standard Template Library)** — библиотека шаблонных контейнеров и алгоритмов C++, которой пользуются в 95% олимпиадных решений. Знание того, что уже есть в STL, экономит часы кодинга.

* **Главный принцип:** не пишите своё то, что уже реализовано, проверено и оптимизировано в <algorithm> и <vector>.
* **Главное правило:** если операция в каком-то контейнере быстрее — выбирайте самый быстрый контейнер, который поддерживает нужное.

---

## 🧮 Карта контейнеров: когда что брать

| Контейнер                        | Вставка        | Поиск/доступ   | Когда выбирать                                  |
| :------------------------------- | :------------- | :------------- | :---------------------------------------------- |
| `vector<T>`                      | $O(1)$ в конец | $O(1)$ по индексу | **Базовый выбор** для массивов                |
| `string`                         | $O(1)$ в конец | $O(1)$         | Строки                                          |
| `deque<T>`                       | $O(1)$ оба конца | $O(1)$ по индексу | Структуры «с двух концов»                    |
| `stack<T>`                       | $O(1)$         | $O(1)$ верх     | Стек (рекурсия, скобки)                         |
| `queue<T>`                       | $O(1)$         | $O(1)$ фронт    | BFS                                             |
| `priority_queue<T>`              | $O(\log n)$    | $O(1)$ максимум | Это **куча**: извлекать экстремум за $O(\log n)$|
| `set<T>` / `multiset<T>`         | $O(\log n)$    | $O(\log n)$     | Отсортированные уникальные данные               |
| `map<K,V>`                       | $O(\log n)$    | $O(\log n)$     | Словарь «ключ→значение»                         |
| `unordered_set` / `unordered_map`| $O(1)$ средн.  | $O(1)$ средн.   | Хэш-таблицы (без сортировки); ср. $O(n)$ в худшем |
| `array<T, N>`                    | —              | $O(1)$          | Фиксированный размер, на стеке                  |

> [!⚠️] Когда не брать
> `list<T>` на олимпиадах почти бесполезен. `vector` делает всё то же быстрее. Сортировка «списка» — сплошное страдание.

## 🛠️ Ключевые приёмы с `vector`

* `v.reserve(n)` — выделить место заранее (без пересоздания массива при росте).
* `v.push_back(x)` / `v.emplace_back(args...)` — во втором случае объект строится сразу на месте (быстрее, нет лишней копии).
* `v.begin(), v.end()` — итераторы, везде передаются полуинтервалом `[begin, end)`.
* `v.erase(unique(v.begin(), v.end()), v.end())` — удаление подряд идущих дублей после сортировки.
* `lower_bound(v.begin(), v.end(), x)` — первый элемент **≥ x**; `upper_bound` — первый **> x**. Δают индекс для [[Бинарный поиск]].

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

int main() {
    vector<int> v = {5, 2, 8, 2, 1};
    sort(v.begin(), v.end());                 // [1, 2, 2, 5, 8]

    auto it = lower_bound(v.begin(), v.end(), 3);
    cout << "Первый >= 3: " << *it << " (индекс " << (it - v.begin()) << ")" << endl;

    v.erase(unique(v.begin(), v.end()), v.end()); // [1, 2, 5, 8]

    // next_permutation — все перестановки в лексикографическом порядке!
    vector<int> p = {1, 2, 3};
    do {
        cout << p[0] << p[1] << p[2] << endl;
    } while (next_permutation(p.begin(), p.end()));

    return 0;
}
```

## 💻 Сортировка структур и лямбда-компараторы

Сортировка по своим правилам — главный навык STL. Сортировать можно **структуры** и даже **несколько полей** через кортежи:

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

struct Voenkomat {  // Хм, лучше что-то нейтральное: ученик
    string name;
    int points;
    int age;
};

int main() {
    vector<Voenkomat> v = {
        {"Аня", 95, 17},
        {"Боря", 95, 16},
        {"Витя", 90, 17},
    };

    // 1) Лямбда-компаратор: по баллам убывание, при равенстве — по возрасту возрастание
    sort(v.begin(), v.end(), [](const auto& a, const auto& b) {
        if (a.points != b.points) return a.points > b.points;
        return a.age < b.age;
    });

    // 2) Проще: кортеж ломает порядок только в меньшую сторону,
    //    поэтому для «убывание баллов» пишем минус
    sort(v.begin(), v.end(), [](const auto& a, const auto& b) {
        return make_tuple(-a.points, a.age) < make_tuple(-b.points, b.age);
    });

    for (auto& x : v)
        cout << x.name << " " << x.points << " лет=" << x.age << endl;

    return 0;
}
```

**Компаратор — строгий порядок (strict weak ordering):** если `a < b` истинно, то `b < a` обязан быть ложным, иначе сортировка сломается (UB).

## 🧮 Приоритетная очередь: боль компараторов

В `priority_queue` по умолчанию максимум наверху. Чтобы поменять порядок, **первый шаблонный аргумент** — тип, **второй** — контейнер, **третий** — компаратор:

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <utility>

using namespace std;

// Кастомный компаратор: приоритет тем больше, чем меньше второй элемент пары.
// В priority_queue «верх» — элемент, который компаратор считает НАИБОЛЬШИМ,
// поэтому для min-кучи компаратор возвращает «a выше b», когда a.second > b.second
struct CmpBySecond {
    bool operator()(const pair<int, int>& a, const pair<int, int>& b) const {
        return a.second > b.second; // > => сверху — элемент с минимальным second
    }
};

int main() {
    // Min-куча: наверху минимальный элемент
    priority_queue<int, vector<int>, greater<int>> minHeap;

    // Max-куча (по умолчанию)
    priority_queue<int> maxHeap;

    // Кастом: приоритет по второму элементу пары
    priority_queue<pair<int, int>, vector<pair<int, int>>, CmpBySecond> custom;

    minHeap.push(5); minHeap.push(1); minHeap.push(3);
    cout << minHeap.top() << endl; // 1

    custom.push({7, 2}); custom.push({1, 5});
    cout << custom.top().first << endl; // {7, 2} — второе значение меньше
    return 0;
}
```

Именно Min-куча используется в оптимизированном [[Алгоритм Дейкстры]]: `priority_queue<pair<int,int>, vector<pair<int,int>>, greater<...>>`.

## 🔍 Полезные алгоритмы из `<algorithm>`

| Функция                      | Что делает                                          |
| :--------------------------- | :-------------------------------------------------- |
| `sort`, `stable_sort`        | Сортировка; `stable` сохраняет порядок равных       |
| `nth_element`                | Найти k-й наименьший элемент за $O(n)$              |
| `partition`, `remove_if`     | Разбиение по условию                                |
| `reverse`                    | Разворот                                           |
| `rotate`                     | Циклический сдвиг                                   |
| `accumulate`                 | Сумма (или любая свёртка из `<numeric>`)            |
| `fill`, `iota`               | Заполнение значениями / последовательностью         |
| `min_element`, `max_element` | Минимум/максимум в диапазоне                        |
| `unique`                     | Удаление подряд идущих дублей                       |
| `next_permutation`           | Перебор всех перестановок                           |

> [!💡] Наблюдение
> Обычно дешевле **отсортировать и использовать `lower_bound`**, чем держать `set`: сортировка кэш-дружелюбнее и быстрее в разы. `set`/`map` берите, когда есть динамические вставки/удаления посреди работы.
