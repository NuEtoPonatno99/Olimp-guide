# Бинарный поиск

**Бинарный поиск** находит позицию элемента в отсортированном массиве, а также применяется как «поиск по ответу» для любой **монотонной** функции. За каждый шаг область поиска уменьшается вдвое.

* **Сложность по времени:** $O(\log n)$ — лучший результат, что можно получить, работая только сравнениями.
* **C++ готовое:** `lower_bound` / `upper_bound` / `binary_search` из `<algorithm>`.
* **Главный шаблон «по ответу»:** если для «ответа» $x$ выполняется монотонное условие, ищем границу перехода «да/нет» за $O(\log \text{maxAns})$.

---

## 🛠️ Идея

Инвариант: ответ **всегда лежит** на отрезке $[l, r]$. Мы неуклонно сужаем отрезок вдвое, пока не останется ровно одна точка.

Пишем **вручную**, чтобы точно контролировать границы (готовый `lower_bound` — для массивов, но для «поиска по ответу» нужен свой):

```cpp
#include <iostream>
#include <vector>

using namespace std;

// Первый индекс, где a[i] >= x  (массив должен быть отсортирован)
int lowerBound(const vector<long long>& a, long long x) {
    int l = 0, r = (int)a.size(); // r - «первый не-кандидат»
    while (l < r) {
        int m = l + (r - l) / 2;  // защита от переполнения l + r
        if (a[m] < x) l = m + 1;  // m слишком левый, ответ правее
        else          r = m;      // m подходит, но ответ может быть левее
    }
    return l;
}

int main() {
    vector<long long> a = {1, 2, 2, 5, 8};
    cout << "Первый >= 3: " << lowerBound(a, 3) << endl;  // индекс 3 (значение 5)
    return 0;
}
```

* Полуинтервал `[l, r)`: **Ответ всегда в $[l, r]$**, но цикл оставляет `[l, r)` так, что `l` — искомый первый индекс.
* `m = l + (r - l) / 2` вместо `(l + r) / 2` — защита от переполнения при больших `l` и `r`.
* Для поиска **последнего** элемента с условием работает зеркальный шаблон `if (ok(m)) l = m; else r = m - 1;`.

## 💻 Бинарный поиск «по ответу»: задача о коровах

Классика: на прямой $n$ позиций, нужно поставить $c$ коров так, чтобы **минимальное** расстояние между ними было максимальным.

Проверка «можно ли расставить с расстоянием $\ge d$» жадная и монотонная: если с $d$ можно — значит можно и с меньшим. Значит по $d$ работает бинарный поиск.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

// Жадная проверка: хватит ли расстояния d, чтобы расставить cows коров
bool canPlace(const vector<int>& pos, int cows, int d) {
    int placed = 1;               // первую корову ставим в самую левую позицию
    int last = pos[0];
    for (int i = 1; i < (int)pos.size(); i++) {
        if (pos[i] - last >= d) { // ставим следующую корову
            placed++;
            last = pos[i];
            if (placed == cows) return true;
        }
    }
    return false;
}

int main() {
    int n, c;
    cin >> n >> c;
    vector<int> pos(n);
    for (int i = 0; i < n; i++) cin >> pos[i];
    sort(pos.begin(), pos.end());

    // Монотонность: true, true, ..., true, false, false...
    // Ищем последний d, который даёт true
    int l = 1, r = pos.back() - pos.front();
    while (l < r) {
        int m = l + (r - l + 1) / 2;  // +1, чтобы при l+1==r двигался вверх
        if (canPlace(pos, c, m)) l = m;    // m подходит — ищем больше
        else                    r = m - 1; // m не подходит — ищем меньше
    }
    cout << "Максимальное минимальное расстояние: " << l << endl;
    return 0;
}
```

> [!⚠️] Две разные формулы деления
> **Поиск первого «да»:** `if (check(m)) r = m; else l = m + 1;` — середина `l + (r - l) / 2`.
> **Поиск последнего «да»:** `if (check(m)) l = m; else r = m - 1;` — середина `l + (r - l + 1) / 2` (важно! иначе виснет на двух элементах).

## 💻 Бинарный поиск с вещественной точностью

У вещественного поиска нет границ-целых — просто повторяем фиксированное число раз:

```cpp
#include <iostream>
#include <cmath>

using namespace std;

double f(double x) { return x * x - 2.0; } // монотонно растёт на [0, 10]

// Корень уравнения f(x) = 0 на отрезке [l, r], где f монотонна
double binarySearchDouble() {
    double l = 0.0, r = 10.0;
    // 100 итераций хватит с бешеным запасом (2^-100 точность)
    for (int iter = 0; iter < 100; iter++) {
        double m = (l + r) / 2.0;
        if (f(m) < 0) l = m;   // корень правее
        else          r = m;   // корень левее
    }
    return (l + r) / 2.0;      // sqrt(2) ≈ 1.41421
}

int main() {
    cout << binarySearchDouble() << endl; // 1.41421 = sqrt(2)
    return 0;
}
```

> [!⚠️] Не путайте с [[Тернарный поиск]]!
> Бинарный ищет **корень/границу монотонной** функции. Тернарный — **экстремум** (максимум/минимум), где функция сначала растёт, потом убывает. Если функция «горбатая» — бинарный не сработает.

## 🔍 Где ещё применяется

| Задача                                           | Что ищем по ответу                     |
| :----------------------------------------------- | :------------------------------------- |
| Проверка существования подотрезка с условием     | Размер окна / порог суммы              |
| Минимизация «максимального времени/расстояния»   | Границу max-значения                   |
| Планирование работ (пусть все < X)               | Верхнюю границу нагрузки               |
| Вещественные корни уравнений                     | Точку перехода знака                   |
| Поиск в std: `lower_bound`, `upper_bound`        | Границы вставки                        |

* Тесно связан с [[Префиксные суммы и разности]] (проверка условия за $O(1)$ позволяет крутить бинарный поиск).
* Если массив отсортирован — ищите сначала `lower_bound`, прежде чем писать своё.

## 🔍 Нюансы

* **Переполнение в вещественных:** используйте `long double` для высокой точности в жёстких задачах.
* **Ровная граница:** при поиске «по ответу» всегда проверяйте крайние значения (`l = 1` или концы отрезка) — иногда оптимальный ответ ровно на границе и монотонность «съедена».
* **$O(\log)$ замечательно быстр:** $\log_2(10^9) \approx 30$ итераций — проверка может быть хоть за $O(n)$, суммарно всё равно ~$30n$.
