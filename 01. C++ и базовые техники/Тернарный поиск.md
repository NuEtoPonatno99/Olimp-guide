# Тернарный поиск

**Тернарный поиск** находит **экстремум** (максимум или минимум) **унимодальной** функции — функции, которая сначала монотонно растёт, а потом монотонно убывает (или наоборот). Правильная форма — «горб» или «впадина».

* **Сложность по времени:** $O(\log \frac{R-L}{\varepsilon})$, где $\varepsilon$ — желаемая точность.
* **Ограничение:** функция обязана быть унимодальной. Для **монотонной** функции используйте [[Бинарный поиск]], не тернарный.

---

## 🛠️ Вещественная версия

Берём отрезок $[l, r]$ и две точки-середины $m_1$ и $m_2$, делящие его на ~3 части (обычно $\frac{l+r}{2}$ и чуть правее). Сравнивая значения в точках, отбрасываем треть отрезка, где экстремума точно нет:

* Если $f(m_1) < f(m_2)$ (для поиска максимума) — экстремум правее $m_1$, отбрасываем левую часть.
* Иначе — экстремум левее $m_2$.

```cpp
#include <iostream>
#include <cmath>

using namespace std;

// Унимодальная фукнция: например, прибыль в зависимости от цены билета
double profit(double price) {
    return -price * price + 10.0 * price - 4.0; // парабола с максимумом
}

double ternaryMax(double l, double r) {
    // 200 итераций дают огромную точность
    for (int iter = 0; iter < 200; iter++) {
        double m1 = (2.0 * l + r) / 3.0;    // 1/3 отрезка
        double m2 = (l + 2.0 * r) / 3.0;    // 2/3 отрезка
        if (profit(m1) < profit(m2))
            l = m1;  // максимум правее m1
        else
            r = m2;  // максимум левее m2
    }
    return (l + r) / 2.0;
}

int main() {
    double x = ternaryMax(0.0, 10.0);
    cout << "Оптимальная цена: " << x << ", прибыль: " << profit(x) << endl;
    return 0;
}
```

* Итерации лучше, чем `while (r - l > eps)`: при малых `eps` цикл может зациклиться из-за точности `double`. 200 фиксированных итераций всегда заканчиваются.
* Для поиска минимума знак сравнения меняется на противоположный: `if (f(m1) > f(m2))`.

## 💻 Целочисленная версия

Экстремум на краю отрезка отделяется проверкой соседей — это ломает унимодальность на маленьких отрезках. Поэтому работаем, пока длина > 3, а остаток проверяем тупо:

> [!⚠️] Ловушка дискретности
> Дискретная функция может быть унимодальной «на глаз», но терять вид экстремума из-за равенств. Тернарный по целым — всегда оставляйте хвост для перебора соседей.

```cpp
#include <iostream>

using namespace std;

// Массив с единственным максимумом: растёт, потом убывает
int a[] = {1, 3, 7, 12, 20, 19, 15, 8, 2};

int peak() {
    int l = 0, r = (int)(sizeof(a) / sizeof(a[0])) - 1;
    while (r - l > 3) {          // пока отрезок длиннее 4 точек
        int m1 = l + (r - l) / 3;
        int m2 = r - (r - l) / 3;
        if (a[m1] < a[m2]) l = m1;  // пик правее
        else              r = m2;   // пик левее
    }
    int best = a[l];
    for (int i = l + 1; i <= r; i++) best = max(best, a[i]); // добиваем хвост
    return best;
}

int main() {
    cout << "Пик массива: " << peak() << endl; // 20
    return 0;
}
```

## 🔍 Когда на самом деле нужен тернарный поиск

| Признак в задаче                                  | Вывод                                                |
| :------------------------------------------------ | :--------------------------------------------------- |
| «Найдите точку, где значение функции минимально/ максимально» и функция непрерывная унимодальная | ✅ Тернарный поиск |
| Функция монотонная (только вверх или только вниз) | ✅ [[Бинарный поиск]] — а не тернарный |
| Функция вогнутая/выпуклая, значение зависит от одного параметра | ✅ Тернарный поиск (выпуклость = унимодальность) |
| Несколько экстремумов                             | ❌ Никакой из них; нужен перебор или [[Динамическое программирование. Основы]] |

**Связки:** задачи «минимизируем максимум» часто решаются и бинарным поиском, и тернарным. Если целевая функция унимодальна по решаемому параметру — тернарный; если условие-проверка монотонно (да/нет) — бинарный.

> [!💡] Не выдумывайте тернарный поиск в задачах на ДП
> Оптимизация ДП (Convex Hull Trick и прочее) — отдельная тема: см. [[Оптимизации ДП]]. Там «выпуклость» используется, но с другими инструментами.
