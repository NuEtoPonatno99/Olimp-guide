# DSU (СНМ)

**DSU (Disjoint Set Union, СНМ — система непересекающихся множеств)** — структура данных для объединения множеств и проверки «в одном ли множестве» элементы. С эвристиками **сжатия пути** и **объединения по размеру** работает почти за $O(1)$ амортизированно: $O(\alpha(n))$ на операцию, где $\alpha$ — обратная функция Аккермана (практически константа $< 5$).

* **Операции:** `find(x)` — корень множества, `unite(a, b)` — слить два множества. Обе за $O(\alpha(n))$.
* **Память:** один массив предков + массив размеров — $O(n)$.
* **Две эвристики — условие скорости:** сжатие пути (переподвешивание при поиске) и union by size (вешать меньшее под большее). Без них деградирует до $O(n)$.
* **База для:** [[Графы]] (компоненты связности), алгоритма Краскала (MST), оффлайн-задач «соединение во времени».

---

## 🛠️ Идея

Каждое множество — дерево, где элементы указывают на родителей, а «корень» — представитель множества. `find` поднимается по родителям, дополнительно **сжимая путь** (перевешивая на корень — следующий поиск мгновенный). `unite` привязывает корень меньшего дерева к корню большего.

```cpp
#include <iostream>
#include <vector>

using namespace std;

struct DSU {
    vector<int> parent, sz;

    DSU(int n) : parent(n), sz(n, 1) {
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {                              // итеративно со сжатием
        int root = x;
        while (parent[root] != root) root = parent[root];
        while (parent[x] != x) {                   // вторым проходом вешаем на корень
            int nxt = parent[x];
            parent[x] = root;
            x = nxt;
        }
        return root;
    }

    bool unite(int a, int b) {
        a = find(a);
        b = find(b);
        if (a == b) return false;                  // уже в одном множестве
        if (sz[a] < sz[b]) swap(a, b);             // большее становится корнем
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }

    bool same(int a, int b) { return find(a) == find(b); }
};

int main() {
    DSU dsu(5);
    dsu.unite(0, 1);
    dsu.unite(2, 3);
    dsu.unite(3, 4);
    cout << dsu.same(0, 1) << "\n";                // 1
    cout << dsu.same(1, 2) << "\n";                // 0
    dsu.unite(1, 2);                               // связывает два множества
    cout << dsu.same(1, 4) << "\n";                // 1
    return 0;
}
```

Рекурсивная версия `find` короче:

```cpp
int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
```

Но может упереться в стек на глубоких цепочках (до сжатия). Итеративная выше — страховка.

## 💻 Вариации и трюки

### Количество компонент

`unite` возвращает `true` при реальном слиянии — поэтому число компонент = стартовое $n$ минус число успешных `unite`. Удобно для [[Графы]]/*построение дерева без циклов*.

### Удаление/«острова, отключаемые во времени» (offline)

Массивы больших задач часто дают «сначала удаляем рёбра». Offline-приём: **обратные запросы** — добавляем рёбра в обратном порядке времени. Классика для:
* «компоненты связности после $k$ удалений»;
* «восстановление графа» (добавление рёбер по весам — это Краскал).

### DSU с откатом (rollback)

Для алгоритмов «вперёд-назад» (например, делимость на равные отрезки) хранят историю изменений `parent/sz` и `undone` вручную. Стоит отдельной заметки — здесь только знать, что существует.

### Поддержка «веса» ребра внутри множества

Если в `unite` нужно хранить ещё, например, максимальный вес ребра в компоненте (для Краскала) — вести `mx[v]` и обновлять при слиянии корней.

## 🧮 Где применяется

| Задача                                              | Решение через DSU                              |
| :-------------------------------------------------- | :--------------------------------------------- |
| Компоненты связности графа                          | перебор рёбер + `unite`                         |
| Краскал (MST)                                       | сортировка рёбер по весу + `unite`              |
| «В одном ли множестве» после серии объединений      | `same(a, b)`                                    |
| Число компонент после удалений (оффлайн)            | reversed-time приём                              |
| Покраска/сжатие диапазонов (например, закрасить $[l,r]$) | DSU «следующая непокрашенная позиция» — см. ниже |
| Нахождение периодов/перестановок                    | объединение индексов по правилу                 |

### DSU «следующая непокрашенная»

Окраска клеток/точек с пропуском уже посещённых — замена `set<int>`:

```cpp
vector<int> nxt;  // nxt[i] = "следующий непокрашенный индекс >= i"

for (int i = 0; i < n; i++) nxt[i] = i;
function<int(int)> get = [&](int i) {
    return nxt[i] == i ? i : nxt[i] = get(nxt[i]);
};
// когда покрасили позицию p: nxt[p] = get(p + 1);
```

`get(i)` даёт первую непокрашенную $\ge i$ — в сумме каждый индекс посещается один раз, $O(n \cdot \alpha(n))$. Тот же приём — «найти следующий неиспользованный» в жадных алгоритмах.

## 🔍 Нюансы

* **Сжатие пути без union by size** (или наоборот) — уже не $O(\alpha(n))$. Нужны **обе** эвристики для заявленной сложности.
* **Рекурсивный `find`** на глубине до сжатия может упасть по стеку при $n \sim 10^7$ — итеративный надёжнее.
* **`unite` возвращает `false`** если уже в одном множестве — это и предотвращает циклы в минимальном остовном/связующем построении.
* **Работает только с «нерастущим» набором множеств:** не умеет *разъединять* множества (для этого — оффлайн + обратное время или DSU с откатом).
* **long long в `sz`** не нужен (размеры до $n$), а вот в суммах весов — да.
* **Сжатие пути меняет дерево** — если позже понадобятся «предки внутри множества», не сжимать пути (или сжимать только корни).

## 🔗 Дальше

DSU — базовый кирпич для алгоритмов на [[Графы]]: от связности до MST (Краскал). Для «следующего свободного» пригодится и [[Дерево отрезков]] (поиск первого $\ge x$). Сложные оффлайн-связки (LCA, динамическое добавление рёбер) — отдельная тема; начать с DSU+развороты времени.
