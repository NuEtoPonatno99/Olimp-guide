# Sparse Table (RMQ)

**Sparse Table** — структура для **статичных** запросов на отрезке: минимум/максимум/НОД/AND/OR за $O(1)$ с предподсчётом $O(n \log n)$. Работает только когда массив **не меняется** — зато отвечает мгновенно и код в два раза короче [[Дерево отрезков]].

* **Операции:** запрос на отрезке за $O(1)$ (для idempotent-операций), предподсчёт $O(n \log n)$.
* **Память:** $O(n \log n)$ (для RMQ обычно `int st[LOG][n]`).
* **Ключ к $O(1)$:** операция должна быть **идемпотентной** ($\min(\min(a,b),c) = \min(a, \min(b,c))$) — тогда можно «накрыть» отрезок двумя перекрывающимися блоками.
* **Не работает для сумм/XOR** (нужны непересекающиеся блоки) — там [[Дерево отрезков]] или [[Дерево Фенвика]].

---

## 🛠️ Идея

`st[k][i]` = результат операции на отрезке $[i, i + 2^k - 1]$ длины $2^k$.

Предподсчёт по формуле «половина + половина»:

$$st[k][i] = op\big(st[k-1][i],\ st[k-1][i + 2^{k-1}]\big)$$

Запрос $[l, r]$: берём $k = \lfloor \log_2(r - l + 1) \rfloor$ и «склеиваем» два пересекающихся блока по $2^k$:

$$op\big(st[k][l],\ st[k][r - 2^k + 1]\big)$$

Для **идемпотентных** операций перекрытие неважно — ответ тот же. Для суммы перекрытие сломало бы ответ.

## 💻 Реализация (минимум)

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>

using namespace std;

struct SparseTable {
    int n, LOG;
    vector<vector<int>> st;

    SparseTable(const vector<int>& a) {
        n = (int)a.size();
        LOG = 1;
        while ((1 << LOG) <= n) LOG++;          // ceil(log2(n)) + 1
        st.assign(LOG, vector<int>(n));

        for (int i = 0; i < n; i++) st[0][i] = a[i];

        for (int k = 1; k < LOG; k++) {
            for (int i = 0; i + (1 << k) <= n; i++) {
                st[k][i] = min(st[k-1][i], st[k-1][i + (1 << (k-1))]);
            }
        }
    }

    // логарифмы можно предпосчитать, чтобы не вызывать log2 в запросе
    int query(int l, int r) {                   // минимум на [l, r], O(1)
        int len = r - l + 1;
        int k = 31 - __builtin_clz(len);        // floor(log2(len)) — без плавающих
        return min(st[k][l], st[k][r - (1 << k) + 1]);
    }
};

int main() {
    vector<int> a = {4, 2, 3, 1, 5};
    SparseTable sp(a);
    cout << sp.query(0, 4) << "\n";             // 1
    cout << sp.query(1, 3) << "\n";             // 1 (мин. из 2, 3, 1)
    cout << sp.query(3, 4) << "\n";             // 1 (мин. из 1, 5)
    return 0;
}
```

* `31 - __builtin_clz(len)` — целочисленный $\lfloor \log_2 \rfloor$ без `double`. Для `long long`: `63 - __builtin_clzll(len)`.
* Если предпосчитать `lg[i]` на все длины — запрос становится просто парой `st[k][l]`, `st[k][r - 2^k + 1]`.

## 🧮 Где применяется

| Задача                                     | Решение через Sparse Table                          |
| :----------------------------------------- | :-------------------------------------------------- |
| RMQ (минимум/максимум) на подотрезке       | $O(1)$ на запрос, массив неизменен                  |
| НОД/НОК на подотрезке, много запросов     | идемпотентно → $O(1)$                               |
| AND/OR на подотрезке                       | идемпотентность, $O(1)$                             |
| Поиск первой позиции $\ge x$ (с бинпоиском) | спуск/сравнение блоков + [[Бинарный поиск]]        |
| LCA в дереве (через Euler tour + RMQ)      | классическая связка со Sparse Table                 |
| Число различных на подотрезке (2D-версия) | отдельная хитрая техника — вглубь не идём           |

## 🔍 Нюансы

* **Массив должен быть неизменен.** Любое обновление «стоит» пересчёт всей таблицы — $O(n \log n)$. Нужны обновления → [[Дерево отрезков]] / [[Дерево Фенвика]].
* **Идемпотентность обязательна.** Сумма «дважды наслоится» на перекрытии. Для суммы с $O(\log n)$ на запрос — [[Дерево отрезков]] или BIT.
* **Память $O(n \log n)$** — для $n = 10^6$, `LOG ≈ 20`, `int[20e6]` – 80 MB. Скорость отличная, но ест память.
* **`__builtin_clz(0)` не определён** — запрос с пустым отрезком (`l > r`) обрабатывать до вызова.
* **2D/обобщения** усложняют код; для многих задач проще держать `st` как `vector<vector<int>>` — но выигрыш по кэшу у «плоского» варианта заметный.
