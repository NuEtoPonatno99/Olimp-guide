# Дерево отрезков

**Дерево отрезков (segment tree)** — структура данных для **запросов на отрезке с обновлениями** за $O(\log n)$. В отличие от [[Дерево Фенвика]], работает с любыми **ассоциативными** операциями ($\min$, $\max$, сумма, НОД, XOR) — даже без «обратной». Базовый вариант: точечное обновление + запрос на отрезке.

* **Операции:** построение $O(n)$, обновление точки и запрос отрезка за $O(\log n)$.
* **Память:** массив размера $4n$ (или $2 \cdot 2^{\lceil \log_2 n \rceil}$).
* **Обобщение операций:** любая ассоциативная бинарная операция `merge` (сумма, $\min$, $\max$, НОД, xor, …). Это его суперсила против BIT.
* **Массив** лежит «в глубину»: узел `v`, дети `2v` и `2v+1` — компактнее, чем дерево указателей.
* **База для:** [[Дерево отрезков. Ленивые обновления]] (обновление отрезка), [[Декартово дерево (Treap)]] (динамический вариант).

---

## 🛠️ Идея

Массив разбивается на $O(n)$ «подотрезков» — узлов двоичного дерева. Листья — элементы массива, внутренние узлы — результат `merge` детей. Любой запрос `[l, r]` раскладывается не более чем на $O(\log n)$ непересекающихся узлов-подотрезков.

Хранение массивом (как в куче): корень — индекс `1`, левый ребёнок — `2v`, правый — `2v+1`.

$$merge(x, y) = \begin{cases} x + y & \text{для суммы} \\ \min(x, y) & \text{для минимума} \end{cases}$$

## 💻 Реализация (сумма, точечное обновление)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

struct SegTree {
    int n;
    vector<int> t;

    SegTree(const vector<int>& a) {
        n = (int)a.size();
        t.assign(4 * n, 0);
        build(1, 0, n - 1, a);
    }

    void build(int v, int tl, int tr, const vector<int>& a) {
        if (tl == tr) { t[v] = a[tl]; return; }
        int tm = (tl + tr) / 2;
        build(v * 2, tl, tm, a);
        build(v * 2 + 1, tm + 1, tr, a);
        t[v] = t[v * 2] + t[v * 2 + 1];
    }

    int query(int v, int tl, int tr, int l, int r) {
        if (l > r)   return 0;                       // нейтральный элемент
        if (l == tl && r == tr) return t[v];         // узел целиком в запросе
        int tm = (tl + tr) / 2;
        return query(v*2, tl, tm, l, min(r, tm)) +
               query(v*2+1, tm+1, tr, max(l, tm+1), r);
    }

    void update(int v, int tl, int tr, int pos, int val) {
        if (tl == tr) { t[v] = val; return; }
        int tm = (tl + tr) / 2;
        if (pos <= tm) update(v*2, tl, tm, pos, val);
        else           update(v*2+1, tm+1, tr, pos, val);
        t[v] = t[v * 2] + t[v * 2 + 1];
    }
};

int main() {
    vector<int> a = {1, 3, 5, 7, 9, 11};
    SegTree st(a);
    cout << "Сумма [1..3] = " << st.query(1, 0, 5, 1, 3) << "\n";  // 15
    st.update(1, 0, 5, 1, 10);                                     // a[1] = 10
    cout << "Сумма [1..3] = " << st.query(1, 0, 5, 1, 3) << "\n";  // 22
    return 0;
}
```

* `l > r` — пустой запрос возвращает **нейтральный элемент** операции (для суммы — `0`, для $\min$ — `+INF`, для НОД — `0`, для XOR — `0`).
* Без верхних `query`/`update`-обёрток код выше всё равно рабочий — но границы `tl, tr` каждый раз приходится таскать. Ничего страшного, это нормальный олимпиадный стиль.

### Переключение операции

Меняется только `merge`. Например, для минимума:

```cpp
int merge(int x, int y) { return min(x, y); }
// нейтральный в query: int INF = 1e9;
// build / update: t[v] = merge(t[v*2], t[v*2+1]);
```

Всё остальное — то же самое.

## 🧮 Где применяется

| Задача                                                    | Решение                                                  |
| :-------------------------------------------------------- | :------------------------------------------------------- |
| Сумма/$\min$/$\max$/НОД/xor на отрезке + обновления       | базовый segtree, $O(\log n)$                             |
| Хранить «сложный» элемент узла: пару $(sum, min)$ и т.п.  | структура в `t[v]` — иногда и `struct` с обновлением     |
| Первый элемент $\ge x$ на отрезке (lower bound)           | спуск по дереву с обрезанием, $O(\log n)$                |
| Количество различных на отрезке                           | segtree + оффлайн-обработка по правым границам           |
| Слияние отрезков, поиск $(l, r)$ с суммой $\ge k$         | бинарный спуск по дереву                                 |
| Кое-что с обновлением отрезка                             | [[Дерево отрезков. Ленивые обновления]]                  |

## 🔍 Нюансы

* **$4n$ памяти — не магия, а запас:** при $n$ не степени двойки рекурсивный спуск в листья всё равно уходит ниже границы, поэтому берут $4n$. Строго $2 \cdot 2^{\lceil\log_2 n\rceil}$ чуть экономнее, но $4n$ проще.
* **Отсечение пустого запроса `if (l > r)`** — самый частый источник ошибок: забыли — рекурсия выходит за границы отрезка.
* **`int tm = (tl + tr) / 2`** — обратить внимание на переполнение, когда `tl + tr` велики на больших `n`.
* **Recursion depth** — $O(\log n)$, безопасно, но для $10^6+$ лучше поднять стек или писать итеративный вариант.
* **Итеративное дерево отрезков** (снизу вверх) — вдвое быстрее и без рекурсии; для суммы/$\min$ в задачах с большими константами это выигрыш. Изучается отдельно.
* **Отличие от [[Дерево Фенвика]]:** segtree умеет $\min/\max$, НОД без «обратной операции», но тяжелее на ~константу и больше кода. Для чистых сумм BIT обычно «вкуснее».
