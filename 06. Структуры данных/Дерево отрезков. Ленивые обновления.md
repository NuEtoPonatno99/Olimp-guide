# Дерево отрезков. Ленивые обновления

**Ленивые обновления (lazy propagation)** — расширение [[Дерево отрезков]] для **обновления целого отрезка** за $O(\log n)$: «прибавить $x$ ко всем элементам $[l, r]$», «присвоить всем $[l, r]$ значение $v$». Обновление не спускается в каждый лист, а помечает узел «на будущее» (ленивый флаг) и применяется только когда понадобится.

* **Операции:** обновление отрезка и запрос отрезка — обе $O(\log n)$.
* **Память:** $4n$ на значения + $4n$ на отложенные операции (`lazy`).
* **Ключевое правило:** перед спуском в детей обязательно `push` родителя; после изменения детей — пересчёт `pull`.
* **База для:** массовых операций (заполнение, прибавить на отрезке, swap отрезков, перенос), [[Декартово дерево (Treap)]] с lazy.

---

## 🛠️ Идея

Узел хранит **два** массива:

* `t[v]` — корректный **агрегат** отрезка с учётом всех операций;
* `lazy[v]` — операция, которую нужно ещё **применить детям** (например, «добавить 5»). На самом узле она уже учтена в `t[v]`.

Если операция покрывает весь узел — меняем только `t[v]` и `lazy[v]`, не трогая детей. При запросе/обновлении части узла сперва выполняем `push` (передать `lazy` детям), потом рекурсивно спускаемся.

Пример ниже — **прибавить $x$ к отрезку, запрос суммы**:

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

struct LazySegTree {
    int n;
    vector<long long> t, lazy;

    LazySegTree(const vector<int>& a) {
        n = (int)a.size();
        t.assign(4 * n, 0);
        lazy.assign(4 * n, 0);
        build(1, 0, n - 1, a);
    }

    void build(int v, int tl, int tr, const vector<int>& a) {
        if (tl == tr) { t[v] = a[tl]; return; }
        int tm = (tl + tr) / 2;
        build(v*2, tl, tm, a);
        build(v*2+1, tm+1, tr, a);
        t[v] = t[v*2] + t[v*2+1];
    }

    void apply(int v, int tl, int tr, long long x) {
        t[v] += x * (tr - tl + 1);   // операция на весь отрезок
        lazy[v] += x;                 // и «долг» детям
    }

    void push(int v, int tl, int tr) {
        if (lazy[v] == 0) return;
        int tm = (tl + tr) / 2;
        apply(v*2, tl, tm, lazy[v]);
        apply(v*2+1, tm+1, tr, lazy[v]);
        lazy[v] = 0;
    }

    void update(int v, int tl, int tr, int l, int r, long long x) {
        if (l > r) return;
        if (l == tl && r == tr) { apply(v, tl, tr, x); return; }
        push(v, tl, tr);                          // спускаемся — сначала протолкнуть
        int tm = (tl + tr) / 2;
        update(v*2, tl, tm, l, min(r, tm), x);
        update(v*2+1, tm+1, tr, max(l, tm+1), r, x);
        t[v] = t[v*2] + t[v*2+1];                 // пересчёт после детей
    }

    long long query(int v, int tl, int tr, int l, int r) {
        if (l > r) return 0;
        if (l == tl && r == tr) return t[v];
        push(v, tl, tr);
        int tm = (tl + tr) / 2;
        return query(v*2, tl, tm, l, min(r, tm)) +
               query(v*2+1, tm+1, tr, max(l, tm+1), r);
    }
};

int main() {
    vector<int> a = {1, 2, 3, 4, 5};
    LazySegTree st(a);
    st.update(1, 0, 4, 1, 3, 10);                 // +10 к [1..3]
    cout << st.query(1, 0, 4, 1, 3) << "\n";      // 2+10 + 3+10 + 4+10 = 39
    cout << st.query(1, 0, 4, 0, 4) << "\n";      // все элементы = 55
    return 0;
}
```

* `apply` — операция «на целый узел»: для суммы `t += x * len`; для минимума — просто `t += x` (без «длины»).
* `push` проталкивает `lazy` детям **до** ухода вглубь, `lazy` родителя обнуляется.
* `pull` (пересчёт `t[v]` после детей) — в конце каждого `update`.

## 💻 Присваивание отрезка (вместо прибавления)

Другая классика — **«присвоить всем элементам $[l, r]$ значение $v$»**. Меняется `apply` (запись вместо добавления) и появление «отсутствия операции» — обычно `-1`:

```cpp
const int NONE = -1;                    // признак «нет отложенного»
vector<long long> t; vector<int> lazy;  // lazy из long long тоже ок

void apply(int v, int tl, int tr, long long x) {
    t[v] = x * (tr - tl + 1);
    lazy[v] = x;                        // запись, не +x
}

void push(int v, int tl, int tr) {
    if (lazy[v] == NONE) return;
    int tm = (tl + tr) / 2;
    apply(v*2, tl, tm, lazy[v]);
    apply(v*2+1, tm+1, tr, lazy[v]);
    lazy[v] = NONE;
}
```

Фокус: `NONE` должно быть *заведомо не встречающимся* значением операции. Если операций две («прибавить» и «присвоить») — держат две `lazy`-структуры и обдумывают порядок применения (см. Нюансы).

## 🧮 Комбинированные операции

Частый олимпиадный кейс — несколько операций разом (например, «прибавить $x$» **и** «умножить на $x$», «присвоить»). Тогда `lazy` хранит пару `(mul, add)` и применяется в порядке «сначала умножение, потом сложение»:

```cpp
void apply(int v, int tl, int tr, long long mul, long long add) {
    t[v] = t[v] * mul + add * (tr - tl + 1);
    lazy_mul[v] *= mul;
    lazy_add[v] = lazy_add[v] * mul + add;
}
```

Порядок важен: если после «прибавить 5» приходить «умножить на 3», то «долг» «+5» превращается в «+5·3». Комбинированные lazy — большой источник багов, когда операций больше двух.

## 🔍 Нюансы

* **`push` обязателен перед спуском.** И в `query`, и в `update` — иначе дети «забывают» про наложенные на предка операции и ответ ломается.
* **`lazy` нейтральный элемент** — `0` для суммы/$\min$/$\max$, но для присваивания удобнее `NONE = -1`. Всегда проверять «это реальная операция?» прежде чем применять.
* **Типы:** `t` и `lazy` часто `long long` — суммы с ленивыми обновлениями быстро вылезают за `int`.
* **$4n$ на каждый массив**: с двумя lazy-массивами выходит $12n$ памяти. Для больших `n` можно писать итеративный вариант, но рекурсивный обычно проще.
* **Постоянная задержка**: константа в 2–3 раза выше обычного [[Дерево отрезков]] из‑за `push`. Не злоупотреблять, если обновления точечные.
* **Альтернатива — [[Дерево Фенвика]] с разностями** для суммы и «прибавить на отрезке + запрос отрезка» (два BIT). Сегментное дерево выигрывает на гибкости операций.
