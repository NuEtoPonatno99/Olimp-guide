# Дерево Фенвика

**Дерево Фенвика (Fenwick tree, двоичное индексированное дерево, BIT)** — структура данных для **суммы на префиксе с точечными обновлениями** за $O(\log n)$. Работает в $O(\log n)$, куда проще [[Дерево отрезков]] в написании и занимает в разы меньше памяти.

* **Операции:** точка-обновление `add(i, x)` и префиксная сумма `sum(i)` за $O(\log n)$, сумма на отрезке `sum(r) − sum(l−1)`.
* **Память:** один массив размера $n + 1$ — против $4n$ у [[Дерево отрезков]].
* **Хитрость:** позиция хранит сумму «своего» диапазона длины $2^k$ (младший бит индекса).
* **Годится для:** суммы, $\min/\max$ (только с правильным направлением обхода), НОД, count, но **не** для операций «без обратной» (нет разности для минимума).
* **Не умеет:** обновление отрезка (без трюка с разностями) и красивое восстановление ответа — для этого есть [[Дерево отрезков. Ленивые обновления]].

## 🛠️ Идея

Каждый индекс `i` «владеет» отрезком суммы, длина которого — **младший единичный бит** `i & -i`. Например:

* `i = 6 (110₂)` → владеет отрезком длины $2$: элементы `5..6`;
* `i = 12 (1100₂)` → владеет отрезком длины $4$: элементы `9..12`.

**Префиксная сумма** движется вниз по битам: `i -= i & -i`. **Обновление** движется вверх: `i += i & -i`, обновляя все «предки» позиции. На словах сложно — на коде видно сразу:

```cpp
#include <iostream>
#include <vector>

using namespace std;

struct Fenwick {
    int n;
    vector<int> t;                    // 1-индексация: ячейки 1..n
    Fenwick(int n) : n(n), t(n + 1, 0) {}

    void add(int i, int delta) {      // прибавить delta к позиции i
        for (; i <= n; i += i & -i)
            t[i] += delta;
    }

    int sum(int i) {                  // сумма на [1, i]
        int res = 0;
        for (; i > 0; i -= i & -i)
            res += t[i];
        return res;
    }

    int rangeSum(int l, int r) {      // сумма на [l, r]
        return sum(r) - sum(l - 1);
    }
};

int main() {
    Fenwick fw(5);
    fw.add(2, 10);
    fw.add(4, 3);
    cout << fw.rangeSum(2, 4) << "\n"; // 13 (10 + 3)
    cout << fw.rangeSum(1, 3) << "\n"; // 10
    return 0;
}
```

* `i & -i` — в two's complement это и есть младший бит. Работает и для `long long`.
* Начальный массив можно построить за $O(n)$: `t[i] += a[i - 1]; j = i + (i & -i); if (j <= n) t[j] += t[i];` — либо просто $n$ раз вызвать `add`.

## 💻 0-индексация

Внутренние индексы 1‑based, но наружу удобно отдавать 0‑based:

```cpp
void add(int i, int v) {           // i — обычный индекс массива (0..n-1)
    for (i++; i <= n; i += i & -i) t[i] += v;
}
int sum(int i) {                   // сумма a[0..i] (0..n-1)
    int res = 0;
    for (i++; i > 0; i -= i & -i) res += t[i];
    return res;
}
int rangeSum(int l, int r) {       // сумма a[l..r]
    return sum(r) - (l > 0 ? sum(l - 1) : 0);
}
```

Всё остальное без изменений — тот же битовый цикл.

## 🧮 Расширения и применение

| Задача                                          | Приём                                                                                    |
| :---------------------------------------------- | :--------------------------------------------------------------------------------------- |
| Сумма на отрезке, точечные обновления           | базовый BIT, $O(\log n)$ на операцию                                                     |
| Обновление отрезка, запрос точки                | разностный массив: `add(l, x)`, `add(r+1, −x)`, запрос = `sum(i)`                        |
| Обновление отрезка **и** запрос отрезка         | два BIT (см. [[Дерево отрезков. Ленивые обновления]] — там это одна строчка)             |
| Число инверсий                                  | идём слева направо, `sum(i−1)` для каждого элемента, размер алфавита — сжатие координат |
| $k$-я порядковая статистика                     | бинарный подъём по BIT, $O(\log n)$                                                     |
| Количество чисел $< x$ на отрезке, оффлайн      | сортировка по правой границе + BIT по позициям                                          |
| Xor префиксов, максимум (с обновлением)         | своя связка: бинарные операции тоже коммутативны                                        |

### $k$-я порядковая статистика (бинарный подъём)

Если в BIT лежат **частоты** значений, то за $O(\log n)$ ищем наименьший индекс, где префиксная сумма $\ge k$:

```cpp
int kth(int k) {
    int pos = 0;
    for (int step = 1 << 20; step; step >>= 1) {   // 1 << 20 — ближайшая степень >= n
        int nx = pos + step;
        if (nx <= n && t[nx] < k) {
            pos = nx;
            k -= t[nx];
        }
    }
    return pos + 1;
}
```

Тот же приём, что спуск по дереву в [[Дерево отрезков]], но за счёт «суммы до степени двойки» — напрямую по BIT.

## 🔍 Нюансы

* **1-индексация внутри.** Помнить про `+1/−1` на границе: классическая ошибка при переписывании на 0‑based.
* **Операции без «обратной».** Для $\min/\max$/НОД нельзя сделать `sum(r) − sum(l−1)`. Либо хранить структуру для каждого отрезка запроса заново, либо переходить на [[Дерево отрезков]]. Для суммы и XOR обратная есть — это дом BIT.
* **Ноль в индексе.** `i & -i` для `i=0` = 0 → бесконечный цикл. Поэтому 1‑based внутренне и никогда не вызывать `add(0, …)`.
* **Младший бит в long long:** `i & -i` корректно работает, но `1LL << …` в подъёме подбирать под `n`.
* **`vector<int>` → переполнение** при больших суммах: `vector<long long>`.
* **Сходство с [[Префиксные суммы и разности]]:** BIT — префиксные суммы «с динамикой». Не динамика есть — хватает массива.

## 🔗 Дальше

Дерево Фенвика — самый лёгкий представитель семейства «дерево по степени двойки». Когда нужны **более сложные операции или обновления отрезков** — переходим на [[Дерево отрезков]] (на ленивые обновления — [[Дерево отрезков. Ленивые обновления]]). Для **статичных** запросов (без обновлений) быстрее [[Sparse Table (RMQ)]] с ответом за $O(1)$. Младший бит пригодится и в [[Битовые операции]].
