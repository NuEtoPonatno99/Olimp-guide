# Sqrt-декомпозиция и метод Мо

**Sqrt-декомпозиция** — способ разбить массив на блоки размера $\approx \sqrt{n}$ и предпосчитать агрегат каждого блока. Запрос обрабатывает целые блоки (дёшево) и «хвосты» по элементам. Отсюда $O(\sqrt{n})$ на запрос — медленнее [[Дерево отрезков]], но код проще и легче обобщается. **Метод Мо** — оффлайн-техника на идее блоков для запросов на отрезке с «плавающей» статистикой.

* **Sqrt-декомпозиция:** предподсчёт $O(n)$, запрос/обновление $O(\sqrt{n})$.
* **Метод Мо:** отвечаем на все запросы за $O((n + q)\sqrt{n})$, переставляя `l`/`r` по блокам.
* **Что считать:** суммы, минимумы, количество различных элементов, частоты — любые агрегаты, даже «без обратной операции».
* **Базовые списки:** [[Префиксные суммы и разности]] (для сумм без обновлений — быстрее), [[Sparse Table (RMQ)]] (для статичных idempotent — быстрее).

## 🛠️ Sqrt-декомпозиция: идея

Пусть $B = \lceil\sqrt{n}\rceil$. Делим массив на $\lceil n / B \rceil$ блоков, для каждого считаем агрегат (например, сумму). Запрос `[l, r]`:

* левый и правый «хвосты», не попавшие в целые блоки — проходим по элементам, $O(B)$;
* полностью покрытые блоки — берём посчитанный агрегат, $O(n/B)$.

Итого $O(B + n/B) = O(\sqrt{n})$ при $B = \sqrt{n}$.

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>

using namespace std;

struct SqrtBlocks {
    int n, B, cnt;
    vector<int> a, block;

    SqrtBlocks(const vector<int>& arr) {
        a = arr;
        n = (int)a.size();
        B = max(1, (int)sqrt(n) + 1);
        cnt = (n + B - 1) / B;
        block.assign(cnt, 0);
        for (int i = 0; i < n; i++) block[i / B] += a[i];
    }

    void update(int pos, int val) {              // присвоить a[pos] = val
        int b = pos / B;
        block[b] += val - a[pos];
        a[pos] = val;
    }

    int sum(int l, int r) {                      // сумма на [l, r]
        long long res = 0;
        int bl = l / B, br = r / B;
        if (bl == br) {
            for (int i = l; i <= r; i++) res += a[i];
            return res;
        }
        for (int i = l; i < (bl + 1) * B; i++) res += a[i];   // левый хвост
        for (int b = bl + 1; b < br; b++) res += block[b];    // целые блоки
        for (int i = br * B; i <= r; i++) res += a[i];        // правый хвост
        return res;
    }
};

int main() {
    vector<int> a = {1, 2, 3, 4, 5, 6, 7, 8};
    SqrtBlocks sb(a);
    cout << sb.sum(2, 5) << "\n";                 // 3+4+5+6 = 18
    sb.update(3, 100);
    cout << sb.sum(2, 5) << "\n";                 // 3+100+5+6 = 114
    return 0;
}
```

* `i / B` — номер блока; `(bl + 1) * B` — его конец; `(br) * B` — начало правого блока. Ошибки границ — главная болячка sqrt-декомпозиции.
* `B` подбирают: при запросах много, $B \approx \sqrt{n}$; при желании тонкой настройки — $B = \sqrt{n}$ почти всегда «впритык».

## 💻 Метод Мо

Оффлайн: сортируем запросы так, чтобы **`l` и `r` двигались мало**. Сортируем по $(l / B, r)$ — внутри блока `l` «плавает», `r` двигается монотонно.

```cpp
struct Query { int l, r, idx; };

vector<int> moSort(vector<Query>& qs, int B) {
    sort(qs.begin(), qs.end(), [&](const Query& x, const Query& y) {
        int bl = x.l / B, br = y.l / B;
        if (bl != br) return bl < br;
        return (bl % 2 == 0) ? x.r < y.r : x.r > y.r;   // битая змейка — меньше перестановок
    });
    vector<int> ans(qs.size());
    int curL = 0, curR = -1, cur = 0;
    for (auto& q : qs) {
        while (curL > q.l) cur += add(--curL);
        while (curR < q.r) cur += add(++curR);
        while (curL < q.l) cur += remove(curL++);
        while (curR > q.r) cur += remove(curR--);
        ans[q.idx] = cur;
    }
    return ans;
}
```

Здесь `add/remove` — как изменить текущее состояние при включении/исключении позиции. Пример для **количества различных чисел** на отрезке:

```cpp
vector<int> freq;
int add(int pos) { return ++freq[a[pos]] == 1 ? 1 : 0; }   // вклад новой позиции в счётчик уникальных
int remove(int pos) { return --freq[a[pos]] == 0 ? -1 : 0; }
```

Вызывается $O((n + q)\sqrt{n})$ раз, каждое — $O(1)$ (для разности) или $O(\log)$ (для balance). Поэтому метод Мо — «опорный» инструмент для «мутирующих» агрегатов.

| Двумерные «суммы по прямоугольнику»             | sqrt-декомпозиция по обоим измерениям                |

## 🔍 Нюансы

* **Метод Мо — оффлайн.** Нельзя отвечать, если запросы приходят только «вживую» и нельзя переупорядочить.
* **Порядок `while`-циклов** не важен семантически, но важен для констант; главное — двигать `curL`/`curR` в правильную сторону.
* **Константы**: $O((n+q)\sqrt{n})$ с логарифмом на `add/remove` может не пройти на $n = 2\cdot10^5$ с большой $q$ — тогда берут массив размера $n$ и решение без `log`.
* **Оптимизация блоков**: $B \approx \sqrt n$ универсален; для «много запросов, мало массива» $B$ чуть меньше, для большого массива — больше.
* **`int` переполнение** в агрегатах (суммах/частотах) — `long long`.
* **Отличие от [[Дерево Фенвика]]:** там запрос $O(\log n)$, но каждый агрегат «быстрый» только для сумм. Sqrt-декомпозиция терпит любые операции за $O(\sqrt{n})$. Часто проще как затычка, а затем — оптимизация.
