# Декартово дерево (Treap)

**Декартово дерево (Treap = Tree + Heap, декартово дерево поиска)** — двоичное дерево, одновременно являющееся **бинарным деревом поиска по ключу** и **кучей по случайному приоритету**. Балансировка «из коробки»: случайные приоритеты делают дерево почти идеальным независимо от порядка вставок. Главное умение — **операции `merge` и `split`**, из которых собирается всё остальное, за $O(\log n)$ в среднем.

* **Ключевые операции:** `split(v, key)` → два дерева (ключи $< key$ и $\ge key$), `merge(a, b)` → слить. Обе $O(\log n)$.
* **Режимы:** с ключами (множество/map) и **неявное** (implicit treap) — массив с вставкой/удалением/разворотом подстроки.
* **Память:** узел — ключ, приоритет, `left`, `right`, (размер поддерева). $O(n)$ узлов.
* **Случайность = асимптотика:** без случайных приоритетов деградирует до BST. `mt19937` + `uniform_int_distribution` — стандарт.
* **Конкурент [[Дерево отрезков]]:** treap и умеет lazy, и умеет вставки/удаления — но константа выше.

---

## 🛠️ Идея

Каждый узел: `(key, priority)`. Инварианты:

1. **По key** — BST: всё слева $< key$, всё справа $> key$.
2. **По priority** — max-heap: приоритет родителя больше приоритетов детей.

Случайные приоритеты дают высоту $O(\log n)$ с высокой вероятностью — и никакой ручной балансировки, как в AVL/красно-чёрных.

Базовая структура:

```cpp
#include <bits/stdc++.h>

using namespace std;

struct Node {
    int key, prior, sz = 1;
    Node *l = nullptr, *r = nullptr;
    Node(int k) : key(k), prior(rand()) {}
};

int sz(Node* t) { return t ? t->sz : 0; }
void upd(Node* t) { if (t) t->sz = 1 + sz(t->l) + sz(t->r); }
```

## 💻 Операции split / merge

Две операции — и вся жизнь. Всё остальное (insert/erase/range query) — их комбинации.

```cpp
// Разделить по ключу: левое дерево с key < k, правое с key >= k
void split(Node* t, int k, Node*& a, Node*& b) {
    if (!t) { a = b = nullptr; return; }
    if (t->key < k) {
        split(t->r, k, t->r, b);
        a = t;
    } else {
        split(t->l, k, a, t->l);
        b = t;
    }
    upd(a); upd(b);
}

// Слить: все ключи a < все ключи b
Node* merge(Node* a, Node* b) {
    if (!a) return b;
    if (!b) return a;
    if (a->prior > b->prior) {
        a->r = merge(a->r, b);
        upd(a); return a;
    } else {
        b->l = merge(a, b->l);
        upd(b); return b;
    }
}
```

Insert / erase:

```cpp
Node* insert(Node* t, int k) {
    Node *a, *b, *n = new Node(k);
    split(t, k, a, b);
    return merge(merge(a, n), b);
}

Node* erase(Node* t, int k) {
    Node *a, *b, *mid;
    split(t, k, a, b);
    split(b, k + 1, mid, b);
    delete mid;              // в реальных задачах — автоподчистка
    return merge(a, b);
}
```

`split` по `k` и `k+1` выкусывает ровно узел с ключом `k`. Из split/merge собираются и **подсчёты сумм на отрезке**, и k-я статистика.

## 💻 Неявный treap (массив с разрезанием)

Ключей нет — порядок задаёт сама структура, `sz` = размер поддерева. Из-за этого `split` режет **по количеству элементов**.

```cpp
void splitSz(Node* t, int cnt, Node*& a, Node*& b) {   // a — первые cnt элементов
    if (!t) { a = b = nullptr; return; }
    if (sz(t->l) >= cnt) {
        splitSz(t->l, cnt, a, t->l);
        b = t;
    } else {
        splitSz(t->r, cnt - sz(t->l) - 1, t->r, b);
        a = t;
    }
    upd(a); upd(b);
}

Node* insertAt(Node* t, int pos, Node* node) {          // вставить node на позицию pos
    Node *a, *b;
    splitSz(t, pos, a, b);
    return merge(merge(a, node), b);
}

Node* eraseAt(Node* t, int l, int r) {                  // вырезать [l, r)
    Node *a, *b, *mid;
    splitSz(t, l, a, b);
    splitSz(b, r - l, mid, b);
    return merge(a, b);
}
```

Разворот подотрезка — lazy: парой split вырезаем $[l, r)$, вешаем флаг `rev`, мержим обратно. Перед спуском — `push`. Идемпотентно и дёшево:

```cpp
struct Node {
    int key, prior, sz = 1;
    bool rev = false;
    Node *l = nullptr, *r = nullptr;
};

void push(Node* t) {
    if (t && t->rev) {
        swap(t->l, t->r);
        if (t->l) t->l->rev ^= true;
        if (t->r) t->r->rev ^= true;
        t->rev = false;
    }
}
```

Так получается «dynamic sequence»: вставка/удаление/разворот подстроки за $O(\log n)$ — то, чего не умеет обычный [[Дерево отрезков]].

## 🧮 Где применяется

| Задача                                        | Treap-решение                                      |
| :-------------------------------------------- | :------------------------------------------------- |
| Мультимножество с `k`-й статистикой           | split по size, $O(\log n)$                          |
| Вставка/удаление в середину массива           | неявный treap, splitSz + merge                      |
| Разворот подстроки, циклические сдвиги        | lazy `rev` + split/merge                            |
| Сумма/минимум на подотрезке + мутации         | хранить агрегаты в узле, $O(\log n)$                |
| «Вырезать отрезок и вставить в конец»         | 3 split/merge — за $O(\log n)$                      |
| Слияние двух «двух упорядоченных последовательностей» | `merge(a, b)`, если ключи разделены           |

## 🔍 Нюансы

* **Случайность обязательна.** `rand()` часто урезанный (период, биты) — в олимпиадах используют `mt19937`. Печать `rand()<<15|rand()` — старый трюк против `RAND_MAX`=32767.
* **Стек и рекурсия** $O(\log n)$ — ок, но при неповезло выродится в глубь: редко, «с везением» провал $O(n)$. Случайные приоритеты ж это лечат.
* **Память:** узлы `new`-ятся по одному — на $10^6$ вставок память и скорость страдают. Прогретый пул или `vector<Node>` pool заметно быстрее.
* **`split` по `k` и `k+1` для erase** ломается на дубликатах → для мультимножества лучше split по позиции выбранного элемента.
* **Порядок merge критичен**: `merge(a, b)` требует *все ключи a ≤ все ключи b*. Нарушение — дерево перестаёт быть BST. Это основная ловушка.
* **Сравнение с [[Дерево отрезков]]**: дерево отрезков на статичном массиве — проще и быстрее по константе. Treap нужен когда массив «живой». [[Дерево отрезков. Ленивые обновления]] умеет lazy на статичном массиве; неявный treap — то же на динамическом.
