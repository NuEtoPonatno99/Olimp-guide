# Выпуклая оболочка

**Выпуклая оболочка** множества точек — самый маленький выпуклый многоугольник, содержащий все точки. Строится за $O(n \log n)$ сортировкой точек и одним проходом со стеком. Два самых популярных алгоритма — **Грэхем** и **Эндрю** (монотонная цепочка).

* **Сложность:** $O(n \log n)$ — доминирует сортировка.
* **Идея общая:** все рёбра оболочки — это «повороты налево» (против часовой) при обходе.
* **Эндрю** — упрощённый Грэхем без тригонометрии: сортируем по $x$, потом по $y$, строим нижнюю и верхнюю цепочки.

---

## 🛠️ Идея: чей это угол?

У точек на плоскости есть «угол»: при обходе точки в порядке угла все повороты должны быть «налево». Если встретили поворот «направо» (или «вниз») — значит точка между ними не принадлежит границе, её выкидываем (pop из стека).

Ключевая проверка — знак `cross` из [[Векторы]]: `cross(b - a, c - b)` положителен, если из $a$ в $b$ в $c$ идём против часовой.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

struct Point {
    long double x, y;
};

long double cross(const Point& a, const Point& b, const Point& c) {
    return (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);
}

bool ccw(const Point& a, const Point& b, const Point& c) {
    return cross(a, b, c) > 0; // строго > 0: точки идут против часовой
}
```

## 💻 Алгоритм Эндрю (монотонная цепочка)

Сортируем точки по `(x, y)`, затем строим **нижнюю цепочку** (идём слева направо, сохраняя повороты налево) и **верхнюю** (справа налево). Соединяем.

```cpp
vector<Point> convexHullAndrew(vector<Point> p) {
    sort(p.begin(), p.end(), [](const Point& a, const Point& b) {
        return a.x < b.x || (a.x == b.x && a.y < b.y);
    });

    vector<Point> hull(2 * (int)p.size());
    int k = 0;
    // нижняя цепочка: слева направо
    for (int i = 0; i < (int)p.size(); i++) {
        while (k >= 2 && !ccw(hull[k - 2], hull[k - 1], p[i])) k--; // убрать выпуклый «вниз»
        hull[k++] = p[i];
    }
    // верхняя цепочка: справа налево (заканчиваете на первой точке)
    for (int i = (int)p.size() - 2, t = k + 1; i >= 0; i--) {
        while (k >= t && !ccw(hull[k - 2], hull[k - 1], p[i])) k--;
        hull[k++] = p[i];
    }
    hull.resize(k - 1); // последняя точка == первой, убираем
    return hull;
}
```

* Сортировка по `(x, y)` — нет углов и `atan2`, как у Грэхема. За это Эндрю любят в контестах.
* `ccw` строго `> 0` — внутренние точки на прямой (коллинеарные на границе) выкидываются. Если нужны **все** точки границы, включая на рёбрах — меняйте на `>= 0` и смотрите [[Точка, прямая, отрезок#💻 Точка на отрезке (включая концы)|onSegment]] для аккуратного порядка.

## 💻 Алгоритм Грэхема (сортировка по углу)

Сначала находим самую нижнюю-левую точку (`anchor`), сортируем остальные по **полярному углу** от неё (стокс — от `atan2` или по знакам квадранта), затем тот же проход со стеком:

```cpp
#include <cmath>

Point anchor;

bool polarLess(const Point& a, const Point& b) {
    long double ca = cross(anchor, a, b);
    if (ca != 0) return ca > 0;          // меньший угол => левее
    return cross(anchor, a, a) < cross(anchor, b, b); // при одинаковом угле — ближе
}

vector<Point> convexHullGraham(vector<Point> p) {
    for (Point& pt : p)
        if (pt.y < anchor.y || (pt.y == anchor.y && pt.x < anchor.x))
            anchor = pt;
    sort(p.begin(), p.end(), polarLess);
    vector<Point> hull;
    for (Point& pt : p) {
        while (hull.size() >= 2 && !ccw(hull[hull.size() - 2], hull[hull.size() - 1], pt))
            hull.pop_back();
        hull.push_back(pt);
    }
    return hull;
}
```

> [!⚠️] Разница с Эндрю
> Грэхем сортирует **по углу** и требует аккуратной обработки коллинеарных точек на одном луче (при записи в `polarLess` мы отсеиваем слишком далёкие). Эндрю этого избегает — просто сортировка по координатам. Для контестов почти всегда берите Эндрю.

## 🧮 Когда какой

| Критерий                                     | Эндрю                                | Грэхем                          |
| :------------------------------------------- | :----------------------------------- | :------------------------------ |
| Сортировка                                   | по координатам $O(n \log n)$         | по углу (нужен `atan2`/`quadrant`) |
| Обработка коллинеарных точек на границе      | тривиальна (сортировка)              | сложнее (одна точка на луч)     |
| Точность с `atan2`                            | нет тригонометрии — лучше            | `atan2` на больших координатах шумит |
| Использование в задачах                       | почти всегда                        | редко (нужно по углу обойтись)  |

## 🔍 Нюансы

* **`ccw` строго `>`** убирает точки, лежащие на ребре; `>=` включает их в границу.
* **Эндрю строит обе цепочки** и в конце соединяет — проследите, чтобы первая точка не дублировалась (мы `resize(k - 1)`).
* **Вырожденность:** если все точки на одной прямой — оболочка превращается в отрезок. Алгоритмы это выдают корректно, но проверяйте.
* **Углы vs. координаты:** на больших целых координатах `atan2` теряет точность; Эндрю на чистом `compare` надёжнее.
* **Прямая связь с сортировкой по углу** — [[Сортировка точек по углу]] — решает как построить порядок для Грэхема без дурацких `ang` типа `double`.
