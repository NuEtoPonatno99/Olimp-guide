# Алгоритм Дейкстры

**Алгоритм Дейкстры** находит кратчайшие пути от одной заданной вершины (источника) до всех остальных вершин в графе.

* **Главное условие:** Все веса рёбер должны быть **неотрицательными** ($\ge 0$). Если есть хотя бы одно ребро с минусом, алгоритм сломается (вместо него берут Беллмана — Форда).
* **Сложность по времени:** 
  * Простая реализация: $O(V^2)$
  * С использованием кучи/приоритетной очереди (Min-Heap): $O(E \log V)$ — самый быстрый вариант.

---

## 🛠️ Как работает алгоритм (Жадный принцип)

Алгоритм работает по принципу «жадности»: на каждом шаге мы выбираем самую близкую из ещё не посещённых вершин.

1. **Инициализация:** Расстояние до стартовой вершины равно `0`, до всех остальных — «бесконечность» (`INF`). Все вершины помечаются как *непосещённые*.
2. **Выбор вершины:** Из списка непосещённых выбирается вершина `u` с **минимальным** текущим расстоянием.
3. **Релаксация соседей:** Перебираются все соседи `v` выбранной вершины. Если путь до `v` через `u` короче, чем известный ранее, расстояние обновляется:
   $$dist[v] = \min(dist[v], dist[u] + weight(u, v))$$
4. **Пометка:** Вершина `u` отмечается как *посещённая*. Мы в неё больше никогда не вернёмся.
5. **Повтор:** Шаги 2–4 повторяются, пока остаются непосещённые вершины.

## 💻 Эффективная реализация на C++ (через `priority_queue`)

Использование приоритетной очереди (кучи) позволяет моментально извлекать вершину с минимальным расстоянием за $O(\log V)$.

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>

using namespace std;

const int INF = 1e9;

// Структура для представления ребра: (куда ведет, вес ребра)
struct Edge {
    int to, weight;
};

void dijkstra(int start, int V, const vector<vector<Edge>>& graph) {
    vector<int> dist(V, INF);
    dist[start] = 0;

    // Приоритетная очередь для хранения пар: (расстояние, вершина)
    // По умолчанию std::priority_queue сортирует по убыванию, поэтому используем greater, чтобы получить Min-Heap
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;
    
    // Кладем стартовую вершину: расстояние 0, индекс start
    pq.push({0, start});

    while (!pq.empty()) {
        int d = pq.top().first;
        int u = pq.top().second;
        pq.pop();

        // Пропускаем старые/неактуальные записи в очереди
        if (d > dist[u]) continue;

        // Перебираем всех соседей текущей вершины u
        for (const auto& edge : graph[u]) {
            int v = edge.to;
            int weight = edge.weight;

            // Если нашли путь короче — обновляем расстояние и пушим в очередь
            if (dist[u] + weight < dist[v]) {
                dist[v] = dist[u] + weight;
                pq.push({dist[v], v});
            }
        }
    }

    // Вывод результатов
    cout << "Кратчайшие расстояния от вершины " << start << ":" << endl;
    for (int i = 0; i < V; i++) {
        if (dist[i] == INF) cout << "До " << i << " = Нет пути" << endl;
        else cout << "До " << i << " = " << dist[i] << endl;
    }
}

int main() {
    int V = 5; // Количество вершин (0, 1, 2, 3, 4)
    vector<vector<Edge>> graph(V);

    // Строим взвешенный граф (список смежности)
    graph[0].push_back({1, 4}); // Из 0 в 1 с весом 4
    graph[0].push_back({2, 2});
    graph[1].push_back({2, 3});
    graph[1].push_back({3, 2});
    graph[2].push_back({1, 1});
    graph[2].push_back({3, 4});
    graph[2].push_back({4, 5});
    graph[3].push_back({4, 1});

    dijkstra(0, V, graph);

    return 0;
}
```

## ⚖️ Дейкстра против других алгоритмов путей

* **Быстрее ли [[Алгоритм Флойда-Уоршелла]]?** Да! Для поиска путей из одной точки Дейкстра на куче ($O(E \log V)$) на огромных графах уничтожает Флойд ($O(V^3)$). Даже если запустить Дейкстру из *каждой* вершины по очереди, выйдет $O(V \times E \log V)$, что всё равно эффективнее Флойда на разреженных графах.
* **Быстрее ли [[Алгоритм Беллмана — Форда]]?** Да, Беллман работает за $O(V \times E)$, совершая много «холостых» проверок. Но Дейкстра пасует перед отрицательными рёбрами.

> [!⚠️] Почему Дейкстра ломается на отрицательных весах?
> Алгоритм считает: раз мы выбрали вершину с минимальным весом и зафиксировали её как «посещённую», то короче пути до неё уже быть не может. Но если где-то дальше в графе прячется ребро с весом `-100`, оно могло бы уменьшить этот путь. Дейкстра его просто не перепроверит.
