# Минимальное остовное дерево

**Минимальное остовное (связующее) дерево (MST — Minimum Spanning Tree)** — набор рёбер **связного взвешенного** графа, который соединяет все вершины без циклов и имеет минимальную суммарную массу. Две классики: **Крускал** (жадная сортировка рёбер + [[DSU (СНМ)]]) и **Прим** (Прим — двоюродный брат [[Алгоритм Дейкстры]]).

* **Крускал:** сортируем все рёбра по весу, добавляем, если не создают цикл. $O(E \log E)$ — почти вся работа в сортировке.
* **Прим:** дерево растёт из вершины, на каждом шаге тянем самое дешёвое ребро наружу. $O(E \log V)$ на куче, $O(V^2)$ на матрице для плотных графов.
* **Условие работы:** граф связный; если не связный — получится **остовной лес** (по одному дереву на компоненту).
* **Отрицательные веса не страшны:** в отличие от кратчайших путей, MST минусы не ломают.

---

## 🛠️ Идея (одна жадность, две реализации)

Ключевой факт (лемма о безопасном ребре): **если разрезать граф на две части, самое лёгкое ребро через разрез всегда лежит в каком-то MST**. Отсюда два легальных жадных пути:

* **Крускал:** на каждом шаге берём самое дешёвое из ещё не рассмотренных рёбер и добавляем, если его концы в разных компонентах (иначе цикл). Компоненты — это [[DSU (СНМ)]].
* **Прим:** держим растущее дерево и для каждой вершины «снаружи» храним дешёвейшее ребро, ведущее в него; забираем минимальное. Приоритетная очередь — как в Дейкстре, но минимизируем не `dist[v]`, а `key[v]` = вес ребра до дерева.

## 💻 Крускал (с DSU)

```cpp
#include <bits/stdc++.h>

using namespace std;

struct Edge { int u, v, w; };

struct DSU {
    vector<int> p, sz;
    DSU(int n) : p(n), sz(n, 1) { iota(p.begin(), p.end(), 0); }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;                 // уже связаны — будет цикл
        if (sz[a] < sz[b]) swap(a, b);
        p[b] = a; sz[a] += sz[b];
        return true;
    }
};

int main() {
    int V, E;
    cin >> V >> E;
    vector<Edge> edges(E);
    for (int i = 0; i < E; i++) cin >> edges[i].u >> edges[i].v >> edges[i].w;

    sort(edges.begin(), edges.end(), [](const Edge& a, const Edge& b) {
        return a.w < b.w;
    });

    DSU dsu(V);
    int total = 0, used = 0;
    for (auto& e : edges) {
        if (dsu.unite(e.u, e.v)) {                // концы в разных компонентах
            total += e.w;
            if (++used == V - 1) break;           // дерево готово — раньше выходим
        }
    }
    cout << total << "\n";
}
```

* `unite` возвращает `false`, когда обе вершины уже в одном дереве — это и есть «не добавим цикл».
* Ранний `break` при `V - 1` рёбрах экономит время на больших графах.

## 💻 Прим (с priority_queue)

```cpp
#include <bits/stdc++.h>

using namespace std;

const int INF = 1e9;

int prim(int V, const vector<vector<pair<int, int>>>& g) {
    vector<int> key(V, INF), inTree(V, 0);
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>>
        pq;                                       // (вес ребра, вершина)

    key[0] = 0;
    pq.push({0, 0});
    int total = 0;

    while (!pq.empty()) {
        auto [d, v] = pq.top();
        pq.pop();
        if (inTree[v]) continue;                  // устаревшая запись
        inTree[v] = 1;
        total += d;

        for (auto [to, w] : g[v]) {
            if (!inTree[to] && w < key[to]) {     // улучшаем ребро до дерева
                key[to] = w;
                pq.push({w, to});
            }
        }
    }
    return total;
}
```

До боли похоже на [[Алгоритм Дейкстры]] — отличие только в том, что релаксируем «расстояние до дерева», а не до старта.

Код переходит на $O(V^2)$ простой версии, если вместо `pq` перебирать по матрице смежности — тогда для **плотных** графов $(E \approx V^2)$ это даже быстрее по константе.

## ⚖️ Крускал против Прима

| Критерий                                            | Крускал                        | Прим                          |
| :-------------------------------------------------- | :----------------------------- | :---------------------------- |
| Асимптотика                                         | $O(E \log E)$                  | $O(E \log V)$, $O(V^2)$ на матрице |
| Когда выгоден                                       | разреженные графы, удобно с DSU | плотные графы, есть список смежности |
| Нужен ли [[DSU (СНМ)]]                             | да                              | нет                           |
| Код                                                 | проще (сортировка + DSU)        | чуть сложнее (pq)             |
| Стартовая вершина                                   | не нужна                        | нужна (любая)                 |

Эмпирически на олимпиадках Крускал пишут чаще — он проще и не зависит от представления графа.

## 🧮 Где применяется

| Задача                                                | Решение                              |
| :---------------------------------------------------- | :----------------------------------- |
| Минимальная стоимость объединения сетей/кластеров     | MST, $O(E \log E)$                   |
| Восстановление самого дерева (рёбра)                  | собирать `edge.used` при `unite`      |
| Остовной лес для несвязного графа                     | Крускал без `break` — по компонентам |
| Поиск ребра, обязательно входящего в MST              | подклассы: двойной MST / online, отдельно |
| Базовый шаг в задачах «почти-дерево», фейковые рёбра  | строим MST, затем эвристики          |

## 🔍 Нюансы

* **DSU без эвристик** (сжатие/размер) деградирует — см. [[DSU (СНМ)]], там обе *обязательны* для заявленной сложности.
* **`key[v]` нужно обновлять только для вершин вне дерева** — иначе «зацикливание» Прима на уже взятых вершинах.
* **MST единственно** не всегда: равные веса дают несколько деревьев с одинаковой суммой — оба алгоритма вернут одно из них (какое — зависит от порядка).
* **Связность необходима**: если граф распадается, ответ существовать не может — задачи обычно гарантируют связность.
* **Отрицательные веса и пустые рёбра**: работают, главное — `int`/`long long` для суммы (веса могут быть большими).
