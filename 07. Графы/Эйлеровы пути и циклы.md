# Эйлеровы пути и циклы

**Эйлеров цикл** — маршрут по графу, проходящий по **каждому ребру ровно один раз** и возвращающийся в стартовую вершину. **Эйлеров путь** — тот же обход, но старт и финиш могут различаться (все рёбра по разу, конец не обязан совпадать с началом). Ищется алгоритмом **Хирхольцера** за $O(E)$.

* **Критерий (неориентированный граф):** эйлеров **цикл** есть ⇔ все степени вершин чётные; эйлеров **путь** — ⇔ ровно 2 вершины нечётной степени (это старт и финиш).
* **Критерий (орграф):** цикл ⇔ $\text{in}(v) = \text{out}(v)$ для всех вершин; путь — ⇔ плюс одна вершина с $\text{out} = \text{in} + 1$ (старт) и одна с $\text{in} = \text{out} + 1$ (финиш).
* **Связность обязательна:** все вершины с рёбрами должны лежать в одной компоненте.
* **Хирхольцер:** стек + вырезание рёбер на лету — $O(E)$, код короток.

---

## 🛠️ Идея (почему «чётность»)

Проходя ребро, мы каждый раз «входим» в вершину и «выходим» из неё. Чтобы в конце вернуться в старт и нигде не застрять, число входов должно равняться числу выходов — отсюда чётность. Для пути две «исключительные» вершины: в одной рёбер на вход больше (старт), в другой — на выход (финиш).

Алгоритм Хирхольцера — жадный с подстраховкой: идём по любым рёбрам, и когда застряли — это уже маленький цикл, который «вклеивается» в путь стеком.

## 💻 Хирхольцер (орграф — самый простой случай)

```cpp
#include <bits/stdc++.h>

using namespace std;

vector<vector<int>> g;                       // список смежности: g[v] — исходящие
vector<int> path;                            // стек прохождения

void dfs(int v) {
    while (!g[v].empty()) {                  // вырезаем «на лету» все исходящие
        int to = g[v].back();
        g[v].pop_back();
        dfs(to);
    }
    path.push_back(v);                       // вершина «закрывается» после детей
}
```

Вызов с корректной стартовой вершиной:

```cpp
reverse(path.begin(), path.end());           // итоговый эйлеров путь — перевёрнутый
for (int v : path) cout << v << (v == path.back() ? "\n" : " ");
```

* Вершины кладутся в `path` после завершения рекурсии — порядок получается обратным, нужен `reverse`.
* Сложность $O(E)$: каждое ребро извлекается ровно один раз.

### Неориентированный граф

Из списка надо удалять ребро в **обеих** частях. Проще хранить рёбра с номерами:

```cpp
struct Edge { int to; bool used; };
vector<vector<int>> g;                       // g[v] — номера рёбер
vector<Edge> edges;

void dfs(int v) {
    while (!g[v].empty()) {
        int id = g[v].back();
        g[v].pop_back();
        if (edges[id].used) continue;        // парное ребро уже взяли — пропускаем
        edges[id].used = true;
        edges[id ^ 1].used = true;           // id ^ 1 — парное ребро (кладём пáрами)
        dfs(edges[id].to);
    }
    path.push_back(v);
}
```

Пары рёбер (`id`, `id^1`) — тот же приём, что в сетях [[Теория потоков]]: обратное ребро лежит сразу после прямого.

## 🧮 Где применяется

| Задача                                                    | Решение                                |
| :-------------------------------------------------------- | :------------------------------------- |
| Можно ли нарисовать фигуру одним росчерком                | критерий чётности + Хирхольцер          |
| Восстановить зашифрованную строку по парам «предыдущий–следующий» | эйлеров путь в графе слов       |
| «Обойти все дороги ровно по разу»                         | эйлеров цикл, $O(E)$                   |
| Найти непересекающиеся пути от $s$ к $t$                  | редукция к эйлерову пути/потоку        |
| Проверить «возможность» обхода без повторений ребер       | проверка связности + чётности          |

---

## 🔍 Нюансы

* **Старт выбирать правильно:** если есть вершины нечётной степени (путь) старт — одна из них; в орграфе — `out = in + 1`.
* **`reverse(path)` обязателен** — самая частая ошибка «не обратил порядок».
* **Чётность недостаточна без связности:** изолированная вершина не мешает (рёбер нет), но две несвязанные компоненты — путь невозможен.
* **Петли и кратные рёбра** — работают как есть; для мультиграфов с парными удалениями — схема `id ^ 1` выше.
* **Рекурсия `dfs`** на больших графах + стека — итеративная версия на явном `stack` решает ту же задачу без переполнения.
