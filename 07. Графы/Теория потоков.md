# Теория потоков

**Максимальный поток** — в сети (орграф с пропускными способностями рёбер `cap` и выделенными истоком `s` и стоком `t`) найти максимум, который можно переправить из `s` в `t`. Три схемы: **Форд — Фалкерсон**, его ускорение **Эдмондс — Карп** и стандарт олимпиад — **Диник**.

* **Форд — Фалкерсон:** искать увеличивающий путь DFS-ом; $O(E \cdot F)$, где $F$ — величина ответа (зависит от чисел).
* **Эдмондс — Карп:** тот же, но ищет путь через **BFS** — $O(V \cdot E^2)$.
* **Диник:** BFS-уровни + блокирующие потоки DFS — $O(V^2 E)$, на единичных пропускных $O(E\sqrt{V})$ — стандарт для контестов.
* **Теорема (min-cut):** максимальный поток = минимальный разрез. Полезно, когда спрашивают «разрез» или «минимум суммарной ёмкости разбивающих рёбер».
* **Моделирование:** паросочетания, вершинные разрезы, транспорт, задачи на «пропускную способность» — всё сводится к сети.

---

## 🛠️ Идея (остаточная сеть)

У каждого ребра есть `cap` (ёмкость) и `flow` (текущий поток). Ищем путь из `s` в `t`, где ещё есть «свободная ёмкость» (`cap - flow > 0`), — **увеличивающий путь**. Тонкость: добавляем **обратные рёбра** ёмкости `flow` — они позволяют «откатывать» уже отданный поток, если на предыдущем пути нашли что-то лучше. Именно обратные рёбра дают корректность жадно-итерационного подхода.

Диник ускоряет это тем, что делит процесс на фазы: BFS строит слои (`lvl[v]` — расстояние от `s`), а DFS за фазу «проталкивает» максимально возможный блок — блокирующий поток.

## 💻 Диник (компактная реализация)

```cpp
#include <bits/stdc++.h>

using namespace std;

struct Dinic {
    struct Edge { int to, cap, flow; };
    int n;
    vector<Edge> e;
    vector<vector<int>> g;
    vector<int> it, lvl;

    Dinic(int n) : n(n), g(n) {}

    void addEdge(int u, int v, int cap) {
        g[u].push_back((int)e.size());
        e.push_back({v, cap, 0});
        g[v].push_back((int)e.size());
        e.push_back({u, 0, 0});              // обратное ребро — для отката потока
    }

    bool bfs(int s, int t) {                 // построить слои
        lvl.assign(n, -1);
        queue<int> q;
        lvl[s] = 0;
        q.push(s);
        while (!q.empty()) {
            int v = q.front();
            q.pop();
            for (int id : g[v]) {
                const Edge& ed = e[id];
                if (ed.cap - ed.flow > 0 && lvl[ed.to] == -1) {
                    lvl[ed.to] = lvl[v] + 1;
                    q.push(ed.to);
                }
            }
        }
        return lvl[t] != -1;                 // t достижима — есть фаза
    }

    int dfs(int v, int t, int f) {           // протолкнуть поток по слоям
        if (v == t) return f;
        for (int& i = it[v]; i < (int)g[v].size(); i++) {
            int id = g[v][i];
            Edge& ed = e[id];
            if (ed.cap - ed.flow > 0 && lvl[ed.to] == lvl[v] + 1) {
                int pushed = dfs(ed.to, t, min(f, ed.cap - ed.flow));
                if (pushed) {
                    ed.flow += pushed;
                    e[id ^ 1].flow -= pushed; // пара рёбер: id^1 — обратное
                    return pushed;
                }
            }
        }
        return 0;
    }

    int maxFlow(int s, int t) {
        int flow = 0;
        while (bfs(s, t)) {
            it.assign(n, 0);
            while (int pushed = dfs(s, t, INT_MAX)) flow += pushed;
        }
        return flow;
    }
};
```

Использование:

```cpp
int main() {
    // n вершин, m рёбер…
    Dinic d(n);
    for (int i = 0; i < m; i++) {
        int u, v, c;
        cin >> u >> v >> c;
        d.addEdge(u, v, c);
    }
    cout << d.maxFlow(s, t) << "\n";
}
```

* Обратное ребро кладётся сразу после прямого — поэтому пара индексируется как `id ^ 1`.
* `INT_MAX` как «бесконечность» на прямой DFS — корректно, т.к. свежий поток ограничен пропускными способностями рёбер.

## 🧮 Где применяется

| Задача                                              | Сведение                                                        |
| :-------------------------------------------------- | :-------------------------------------------------------------- |
| Максимальное паросочетание в двудольном графе       | `s → левые (1)` + рёбра + `правые → t (1)`                      |
| Минимальный разрез                                  | max-flow; разрез = вершины, достижимые из `s` после последнего BFS |
| Вершинный разрез («сколько вершин удалить, чтобы разорвать сеть») | раздвоить вершину на `in → out`, внутреннее ребро `cap = 1`    |
| Транспортная задача (много источников/стоков)       | супер-исток `s` и супер-сток `t`                                |
| Многопотоковое планирование задач                   | временные срезы + поток с временными рёбрами                    |

## 🔍 Нюансы

* **`int` против `long long`:** суммы потоков и `cap` легко выходят за `int` — везде, где возможны большие числа, использовать `long long` (в том числе в `dfs`-«бесконечности»).
* **Откаты через `id ^ 1`:** пары рёбер должны класться в `addEdge` строго подряд — нарушение ломает поиск обратного ребра.
* **Диник против малых графов:** на сетях маленького размера простая реализация Дейкстры-на-рёбрах может быть быстрее; но асимптотика Диника надёжнее на больших.
* **Единичные пропускные способности** → $O(E\sqrt{V})$; часто это паросочетания — отдельная оптимизация (Hopcroft–Karp).
* **Min-cut строит разрез** достижимостью из `s` в *остаточной* сети — не из исходной.
