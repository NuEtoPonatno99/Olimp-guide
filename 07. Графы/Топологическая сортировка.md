# Топологическая сортировка

**Топологическая сортировка** — такой порядок вершин **ориентированного ациклического графа (DAG)**, при котором для каждого ребра $u \to v$ вершина $u$ стоит раньше $v$. Семантика — «зависимости»: пока не собрали $u$, нельзя собирать $v$ (сборка проекта, расписание со строгим предшествованием).

* **Условие:** граф должен быть **без циклов** (DAG). Есть цикл — топосорта не существует.
* **Два подхода:** алгоритм **Кана** (степени входа + очередь) и **DFS** (порядок завершения). Оба за $O(V + E)$.
* **Обнаружение цикла:** Kahn и DFS прямо показывают, что цикл есть.
* **База для:** динамики на DAG, построения [[Компоненты сильной связности]]-конденсации, планирования задач.

---

## 🛠️ Идея

Нам нужно «натянуть» вершины в линию так, чтобы стрелки шли только слева направо. Два взгляда на одно:

* **Кана (жадно):** пока есть вершина без входящих рёбер — ставим её первой и вычёркиваем вместе с исходящими. Так и получаем порядок.
* **DFS:** когда завершили обработку поддерева вершины, все «зависимости» из неё уже выведены — значит вершина готова. Записываем в конец и в конце разворачиваем список.

Оба дают **какой-то** (не обязательно единственный) топопорядок — их много.

---

## 💻 Алгоритм Кана (Kahn)

Считаем `indeg[]` (число входящих рёбер). Вершины с `indeg == 0` — кандидаты в «первые». Забираем одну, убираем исходящие рёбра (декремент `indeg` соседей — теперь может освободиться новая вершина):

```cpp
#include <iostream>
#include <vector>
#include <queue>

using namespace std;

vector<int> topoSort(int V, const vector<vector<int>>& g) {
    vector<int> indeg(V, 0);
    for (int v = 0; v < V; v++)
        for (int to : g[v]) indeg[to]++;

    queue<int> q;
    for (int v = 0; v < V; v++)
        if (indeg[v] == 0) q.push(v);

    vector<int> order;
    while (!q.empty()) {
        int v = q.front();
        q.pop();
        order.push_back(v);
        for (int to : g[v])
            if (--indeg[to] == 0) q.push(to);   // сняли последнюю зависимость
    }
    return order;                               // если size() < V — был цикл
}
```

* Если в конце `order.size() < V` — какие-то вершины не попали, в графе цикл.
* Лексикографически минимальный порядок — та же логика с `priority_queue` вместо `queue`.

## 💻 Топосорт через DFS

Трёхцветный обход из [[Обход BFS и DFS]]: цвет `1` = «в процессе» → завершать вершину в момент, когда все её исходящие уже завершены:

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

vector<int> color;          // 0 = не посещена, 1 = в стеке, 2 = готова
vector<int> order;

bool dfs(int v, const vector<vector<int>>& g) {
    color[v] = 1;
    for (int to : g[v]) {
        if (color[to] == 1) return false;                 // цикл
        if (color[to] == 0 && !dfs(to, g)) return false;
    }
    color[v] = 2;
    order.push_back(v);
    return true;
}

// in main:
// bool ok = true;
// for (int v = 0; v < V && ok; v++) if (!color[v]) ok = dfs(v, g);
// if (ok) { reverse(order.begin(), order.end()); /* топопорядок */ }
```

Вершины копятся в порядке завершения — это **обратный** топопорядок, поэтому в конце `reverse`.

---

## 🔍 Как поймать цикл

* **Кана:** `order.size() < V` — цикл. Удобно, когда порядок не критичен, а важно «есть ли цикл».
* **DFS:** возврат `false` при попадании в «серую» вершину — тот же принцип, что в [[Обход BFS и DFS]].
* **2-SAT / почти-цикл:** в циклическом графе топосорт «симулирует» выполнение зависимостей бесконечно — это и есть признак плохой формализации задачи.

## 🧮 Где применяется

| Задача                                                | Решение                                  |
| :---------------------------------------------------- | :--------------------------------------- |
| Порядок сборки проекта по зависимостям                | Kahn/DFS, $O(V + E)$                      |
| Проверка, есть ли цикл зависимостей                   | Kahn: `order.size() < V`                  |
| Лексикографически наименьший топопорядок              | Kahn + `priority_queue`                   |
| Длиннейший/кратчайший путь в DAG                      | топосорт + ДП по порядку, $O(V + E)$      |
| Порядок компонент в [[Компоненты сильной связности]]  | топосорт конденсации «из коробки»         |
| Планирование задач с порядком предшествования         | топосорт + жадная обработка очереди       |

## 🔍 Нюансы

* **Только DAG.** На неориентированный граф топосорт не определяется (ребро двустороннее — обе вершины должны быть «раньше»).
* **Порядок не единственный.** Если задача требует *любой* — оба алгоритма сгодятся; если конкретный (лексикографический) — править структуру очереди.
* **DFS-версия — рекурсивна.** Глубокие цепочки зависимостей — риск переполнения стека; Kahn итеративный и безопаснее на больших $V$.
* **«Порядок завершения» обязан быть развёрнут** `reverse` — классическая ошибка.
* **Динамика на DAG** по топопорядку — стандартный приём (например, длиннейший путь): сначала все «входящие» обработаны, значит переходами можно заполнять ответ слева направо.
