# Хеширование строк

**Полиномиальный хэш** — представление строки числом по базе $p$ по модулю $m$: после предподсчёта за $O(n)$ любые две подстроки сравниваются за $O(1)$. Это базовый инструмент олимпиадных строк: «равны ли подстроки» решается в одну формулу вместо посимвольной проверки.

* **Сложность предподсчёта:** $O(n)$ по времени и памяти.
* **Сложность сравнения подстрок:** $O(1)$.
* **Риск коллизий:** разные строки могут дать одинаковый хэш — страхуются модулем порядка $10^9$ и двойным хэшем.
* **C++ STL:** готовой реализации нет — пишется вручную, ~10 строк.

---

## 🛠️ Идея и формула

Есть строка $s[0..n-1]$. Хэш всей строки — полином по базе $p$ (обычно $p = 31$ или $p = 53$, больше размера алфавита):

$$h = s_0 \cdot p^{n-1} + s_1 \cdot p^{n-2} + \dots + s_{n-1} \pmod m$$

Как и в [[Префиксные суммы и разности]], строим **массив префиксных хэшей** длины $n+1$ и заодно степени $p$:

$$h[i+1] = h[i] \cdot p + s_i \pmod m$$

Тогда хэш подстроки $s[l..r]$ (включительно) — разность двух префиксов, выровненная по степени:

$$hash(l, r) = h[r+1] - h[l] \cdot p^{r-l+1} \pmod m$$

Умножение на $p^{r-l+1}$ выравнивает «виртуальные длины» префиксов: без него формула сравнила бы старшие разряды разных порядков.

Символ кодируем как `s[i] - 'a' + 1` — единицу добавляем, чтобы пустые/повторные части не обнуляли произведение (символ со значением $0$ создаёт ложные совпадения).

## 💻 Реализация

```cpp
#include <iostream>
#include <string>
#include <vector>

using namespace std;

const long long p = 31;       // база (53 при кириллице — всё равно > алфавита)
const long long MOD = 1e9 + 7;

int main() {
    string s;
    cin >> s;
    int n = (int)s.size();

    // h[i+1] = хэш префикса s[0..i], pw[i] = p^i (по модулю MOD)
    vector<long long> h(n + 1, 0), pw(n + 1, 1);
    for (int i = 0; i < n; i++) {
        h[i + 1] = (h[i] * p + (s[i] - 'a' + 1)) % MOD;
        pw[i + 1] = pw[i] * p % MOD;
    }

    // Хэш подстроки [l, r] включительно, O(1)
    auto getHash = [&](int l, int r) {
        long long raw = h[r + 1] - h[l] * pw[r - l + 1] % MOD;
        return (raw + MOD) % MOD; // C++: вычитание может дать отрицательный остаток
    };

    int q;
    cin >> q; // q запросов: «равны ли подстроки s[l1..r1] и s[l2..r2]?»
    while (q--) {
        int l1, r1, l2, r2;
        cin >> l1 >> r1 >> l2 >> r2;
        cout << (getHash(l1, r1) == getHash(l2, r2) ? "equal" : "different") << '\n';
    }
    return 0;
}
```

* `pw[r - l + 1]` — сразу по модулю, поэтому домножаем на `% MOD` в строке `h[l] * pw[...]`.
* `long long` обязателен: `h[i] * p` при $p \sim 10^2$ и модуле $10^9$ доходит до $\sim 10^{11}$.

## 🛡️ Коллизии и двойной хэш

Математика не гарантирует инъективности: строк больше, чем значений по модулю $m$. Защита от ложных срабатываний:

| Подход                        | Вероятность коллизии | Цена                     |
| :---------------------------- | :------------------- | :----------------------- |
| Один модуль $\sim 10^9$       | $\sim 10^{-9}$ на пару | самый дешёвый            |
| Двойной хэш (две пары $p, m$) | $\sim 10^{-18}$ на пару | вдвое памяти и счёта     |
| Случайная база $p$            | почти нулевая        | недетерминизм            |

На Codeforces/контестах обычно хватает одного модуля с базой ~$10^2$; на системах с кастомными злонамеренными тестами берите двойной хэш или случайную базу.

> [!⚠️] Хэш — вероятностное сравнение
> «Хэши равны, значит строки равны» верно с вероятностью, близкой к 1, но формально — не гарантировано. Там, где точность строго обязательна (поиск вхождений, канонические ответы), используйте детерминированный [[Префикс-функция и КМП]] или [[Z-функция]].

## 🔍 Где применяется

| Задача                                    | Решение через хэши                          |
| :---------------------------------------- | :------------------------------------------ |
| Сравнить подстроки за $O(1)$              | префиксные хэши                             |
| Поиск вхождений строки в тексте           | хэш паттерна == хэш окна (за $O(n)$)        |
| Число различных подстрок                  | `unordered_set` всех `hash(l, r)`            |
| Проверка периода строки                   | `getHash(0, n-k-1) == getHash(k, n-1)`       |
| Лексикографическое сравнение подстрок     | хэш + бинпоиск по первой разнице            |
| Палиндромы: проверка за $O(1)$            | хэш прямой и обратной строки (см. [[Палиндромы. Алгоритм Манакера]]) |

* **Все вхождения:** склейка `pattern + '#' + text` и сравнение хэшей окон — альтернатива $\pi$/z-функциям, но вероятностная.
* **Различные подстроки:** $O(n^2)$ пар $(l, r)$ — только при $n \le 2 \cdot 10^3$; дальше нужны суффиксные структуры.

## 🔍 Нюансы

* **Отрицательный остаток:** `%` в C++ при вычитании даёт отрицательное число — всегда добавляйте `MOD` («нормализация»).
* **Ноль у символа:** кодировка `'a' -> 0` делает строки вида «пустой + $a$» неразличимыми по произведению — используйте `+ 1`.
* **Порядок не сохраняется:** хэш не лексикографичен — сортировать строки по хэшу нельзя.
* **Переполнение:** произведение двух `long long` по модулю $10^9$ безопасно; при модулях до $10^{18}$ потребуется `__int128`.
* **Двойной хэш не нужен на практике:** только злонамеренные взломы кастомными тестами заставляют его ставить.
